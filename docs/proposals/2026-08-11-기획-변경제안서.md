## 1. PLAN.md 수정 제안

### [P1-1] 로드맵 압축 — 전체 기간 2~3주 제약 반영

- **현재**: Phase 0(1~2주) + Phase 1(2~3주) + Phase 2(2~3주) = 5~8주+.
- **제안**: PLAN §9의 자체 조항("단기 데드라인이면 DoD를 엔지니어링 관통까지로 한정")을 발동.
  - Phase 0 스파이크 3종을 **1주차 병렬 압축**: ① deepagents 3대 계약 검증 2~3일 ② 품질 스파이크 샘플 포맷별 20건 → **5~8건**으로 축소(리뷰어 2인 유지) ③ 수요 벤치마크 반나절
  - DoD = SPEC §5-(1~4) 엔지니어링 관통. S1(성장 기울기)은 "프로젝트 종료 후 관측 지속 항목"으로 분리
  - kill criteria 중 K1(성장 무신호)은 기간상 판정 불가 → **K2~K4만 활성**
- **근거**: 팀 실행기간 2~3주(요구사항 3). S1 판정에 필요한 캘린더 시간은 개발로 단축 불가함을 PLAN §9가 이미 인정.

### [P1-2] 실험 설계 추가 — SNS당 2계정, auto vs hybrid (요구사항 6)

- **현재**: 단일 운영자 채널 전제. 다중 계정은 Phase 4 후속.
- **제안**: 계정 4개(IG×2, YT×2)를 이번 범위로 승격하고, **완전자동(auto) vs AI+사람(hybrid)** 비교 실험을 §3 범위에 명시.
  - hybrid = Topic Agent가 주제 3~5개 제안 → 사람 선택 → 초안 승인/수정 후 발행
  - 통제 변수: 동일 주제 도메인·발행 슬롯·템플릿·빈도(일 1건). 차이는 mode 하나
  - **구현 최소화 경로**: SPEC FR-Q3의 사람 검수 훅(needs_review + env 플래그)을 "전역 플래그"에서 **채널 단위 mode 컬럼**으로 승격하면 기존 설계 재사용으로 실험 장치가 완성됨
- **근거**: 요구사항 6이 프로젝트의 핵심 실험. 2~3주 안에 "유의미한 인사이트"를 내려면 자기 실험군-대조군 비교가 유일하게 성립하는 설계.

### [P1-3] Topic Agent에 외부 트렌드 소스 추가 (요구사항 16·17)

- **현재**: Topic Agent 입력 = `topic_stats`·`playbook` (내부 데이터만) → 콜드 스타트 시 주제 발굴 경로 공백.
- **제안**: `research_trends` 툴 신설 — 전부 무료 소스, Python 신규 구현(방법론 이식, 코드 재사용 아님):
  Google Trends 급상승 RSS(무인증) · 네이버 검색 API(일 25,000회 무료) · 네이버 데이터랩(일 1,000회) · YouTube 인기영상(1unit) · GitHub 트렌딩/GeekNews RSS(개발 니치) · LLM 웹 그라운딩. 소스 하나 실패 시 조용히 제외하고 계속.
  프롬프트 규칙: "리서치로 확인 안 된 내용은 소재로 쓰지 않는다"(할루시네이션 방지).
- **근거**: 요구사항 16(트렌드 조사 자동화)·17(무료). 트렌드 입력 없이는 첫 사이클부터 주제가 막힘.

### [P2-4] LLM 혼합 전략 (요구사항 17)

- **현재**: Claude(claude-sonnet-5) 단일 → 매 사이클 비용 발생.
- **제안**: deepagents는 모델 주입이 자유로우므로 — 대량·저난도 작업(트렌드 요약·자막 분절·해시태그)은 **Gemini Flash free tier**(일 1,500회), 판단 작업(주제 선정·대본·분석글)은 Claude 유지. FR-P6 비용 상한은 그대로.
- **근거**: 사이클당 비용 절감(요구사항 17). 단, 스택 단순성을 우선하면 Claude 단일 + 상한으로도 무방 — 팀 선택 항목.

### [P2-5] 실행 인프라 확정 필요 (요구사항 7)

- **현재**: "상주 러너 + Docker Compose" — **호스팅 위치 미정**(비용 발생 지점).
- **제안**: 선택지 2개를 미결정 표에 추가하고 1주차 확정 — ① GitHub Actions cron(무료, Python 실행 가능, 웹 독립 충족. 단 상주 러너 설계를 잡 단위로 재편) ② 무료 VM(Oracle 등)에 Compose 상주(설계 유지, 세팅 부담).

### [P3-6] 외부 제약 최신화

- 릴스 최대 3분(2025-01), 쇼츠 최대 3분(2024-10), **유튜브 조회수 집계 변경(2025-03: views=재생 시작, engagedViews=의미 있는 시청 — 수익화 기준)**, 인스타 어그리게이터 추천 제외(2024-04~).

## 2. SPEC.md 수정 제안

### [P1-7] FR-W 일부 필수 승격 (요구사항 11·12·13)

- **현재**: FR-W(대시보드·알림) 전체가 "선택(후속 가능)".
- **제안**:
  - **FR-W4(알림) → 필수.** 구현 확정: Discord 웹훅(무료, ~30줄). 발신 지점 = Publisher 실패 처리부 + 사이클 최상위 catch. 내용 = 오류 분류(auth/quota/spam_block/transient/render) + 원문 + **LLM 원인 분석 1줄**(실패 시 분류명만이라도 발송)
  - **FR-W3(성장 리포트) → 필수 "인사이트 탭"으로 확장.** 계정별 추이·기울기 + **auto vs hybrid 비교 4지표**(글당 조회·좋아요·참여율·팔로워 증가) + 주간 분석글(정직 귀인 규칙 유지)
  - FR-W1(온보딩)·FR-W2(설정)만 선택 유지
- **근거**: 요구사항 11(알림)·12·13(인사이트 탭·그래프)은 필수 기능.

### [P1-8] 알고리즘 신호 최적화 기능 신설 (FR-A 제안) — 딥리서치 근거

> 근거 조사: 3갈래 딥리서치(IG 공식 신호·YT 쇼츠 공식 신호·추천시스템 구조/실증 연구). 상세: PR #4의 `docs/plan/09-알고리즘-신호-최적화.md` 참조.
> 핵심: 두 플랫폼의 공식 랭킹 신호는 소수이고 전부 API로 측정 가능. 알고리즘 "규칙" 역공학은 유효기간이 짧으므로(감사 재현성 연구), **공식 신호 측정 + 자기 계정 기준선 대비 지속 재추정**으로 설계.

|---|---|---|
| FR-A1 | **신호 스코어보드**: 게시물별 공식 신호 계산(IG: shares/reach·likes/reach·saved/reach·avg_watch_time/길이, YT: engagedViews/views·averageViewPercentage) → 계정 기준선 대비 상·하위 태깅 → 리포트 | 상 (공식 신호 1:1) |

| FR-A3 | **초기 확산 조기 판정**: Analyst 폴링을 발행 후 6·24·72h 다회로 설계(시드 테스트 구조가 공식이므로) → 소멸 판정 시 알림+개선 제안 | 중~상 |

### [P1-9] reward 산식 방향 제시 (미결정 항목 §6에 대한 답)

- **제안**: reward = 플랫폼 목적함수와 같은 방향의 신호 가중합 — 완주 근사(avg_watch_time÷길이)·공유율(shares/reach)·engagedViews 비율 중심, 조회수는 log 변환 보조. 계수는 M1 실측 후 사전등록(기존 원칙 유지).
- **근거**: 두 플랫폼 공식 문서·발언이 최적화 대상으로 명시한 신호. 원시 조회수는 heavy-tail이라 학습 신호로 부적합.

### [P2-10] FR-L3 밴딧 활성 조건 명시

- **현재**: 콜드스타트는 균등 탐색. 밴딧 알고리즘은 M6 착수 시 결정.
- **제안**: 표본 계산을 명시 — arm당 최소 10건 필요, 계정당 일 1건 × 3주 = ~20건이므로 **이번 기간 내 밴딧 통계 성립 불가**. "초기 = 균등 탐색 + 플레이북(정성 학습), 밴딧은 arm ≤ 5(훅 패턴 분류 제안)로 축소해 발행 50건 축적 후 활성"을 FR-L3에 추가. K2(학습 무효 폴백)를 선제 적용하는 것과 동일.

### [P2-11] 훅 패턴 분류 추가 (FR-G 확장)

- **제안**: Content Agent가 훅 문장을 본문과 분리 생성하고 패턴 5종(bold_claim / curiosity / story / shock / question)을 `content_item.hook_pattern`에 기록 → FR-Q5 체크리스트 "훅" 항목의 측정 가능화 + 성과 분석 축 + 향후 밴딧 arm.
- **근거**: 숏폼 이탈의 50~60%가 첫 3초에 결정(업계 데이터). 패턴을 기록해야 "무엇이 먹혔나"를 데이터로 답할 수 있음.

### [P2-12] 콘텐츠 정책 안전 신설 (NFR-10 보강)

- **현재**: NFR-10은 계정 안전(워밍업·빈도)만 다룸 — **콘텐츠 정책 리스크 공백**.
- **제안**: "NFR-11 콘텐츠 정책 안전" 신설 — 유튜브 "비진정성 콘텐츠" 정책(2025-07: 템플릿 양산 = 수익화 배제)·인스타 비독창 억제(어그리게이터 = 추천 제외) 대응: ① 매 영상 스크립트 구조를 실질적으로 다르게(FR-A2 유사도 검사와 연동) ② 자체 제작 그래픽(코드 화면·도표) 매 영상 포함 ③ 타인 클립·밈 사용 금지.

### [P3-13] TTS·영상 스택 결정 자료 (미결정 항목 §6 "TTS 엔진"·"디자인 시스템"의 입력)

- **TTS 권장: Google Cloud TTS Chirp 3 HD** — 한국어 무료 최상급, 월 100만 자 무료(일 4건 = 한도의 ~6%), 상업 이용 명시 허용, SSML mark로 **단어별 타임스탬프**(자막 싱크에 필수) 동시 획득. edge-tts는 CI(데이터센터 IP)에서 403 차단 반복 + 약관 그레이존 → 메인 금지.
- **렌더**: ffmpeg+ASS(빠름, 자막 표현력 한계) vs Remotion(단어별 하이라이트 자막 기성품, 3인 이하 무료, 렌더는 별도 프로세스라 Python 코어와 공존 가능) — Phase 0 ② 스파이크에서 양쪽 샘플 제작 후 판정. moviepy는 렌더 속도·자막 표현력 열위로 후보 제외 권장.
- **품질 수치**: 텍스트 안전영역 = 중앙 900×1400(릴스 상단 210/하단 310/우측 84px, 쇼츠 상단 120/하단 300/우측 96px 가림), 시각 변화 2~4초 간격, BGM은 플랫폼 중립 무료 음원(YouTube Audio Library는 유튜브 밖 사용 애매).
