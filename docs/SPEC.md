# 상세 기획 (SPEC) — multiagent-sns

> 상태: **상세기획 (제안)** · 작성 2026-08-10 · 그린필드(과거 자산 재사용 없음, 전부 신규 구현)
> 상위 기획: [`PLAN.md`](PLAN.md) · 데이터 모델: [`ERD.md`](ERD.md) · 다이어그램: [`diagrams/`](diagrams/)
>
> **범위 선언(thin spec)**: 경계 계약·데이터 모델·측정 계획·운영만 못박는다.
> 에이전트 내부 행동(주제 선택 방식·글쓰기 스타일)은 프롬프트/플레이북에 위임하고 스펙으로 고정하지 않는다.
>
> 🔄 **개정 v2 (2026-08-11, 팀 회의 반영)**: 실험 운영(FR-E)·알고리즘 신호 최적화(FR-A)·트렌드 소스(FR-G4)·훅 패턴(FR-G5) 신설, FR-W3·W4 필수 승격, FR-L1~L3 구체화, NFR-11(콘텐츠 정책 안전) 추가, §6 미결정 일부에 결정 자료 반영, §7 최신화.

## 1. 목표 (한 문장)

개발자 주제 콘텐츠를 **IG 피드 게시물·IG 릴스·YouTube 쇼츠**에 **딥에이전트(deepagents)** 가 자동으로 기획·제작·발행하고, 반응(지표)을 학습해 **자기 채널을 키우는** 멀티에이전트 자율 성장 엔진.

## 2. 기능 요구사항 (FR)

### 2.1 에이전트 코어 (FR-C)

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-C1 | 코어 = **deepagents 프레임워크를 그대로 도입**. Orchestrator(main) + 서브에이전트(Topic/Content/Media/Publisher/Analyst/Growth) 구성 | deepagents로 한 사이클(기획→제작→발행→학습)이 관통 실행 |
| FR-C2 | 서브에이전트는 **툴 계약**을 통해서만 외부와 상호작용: `research_trends`·`render_media`·`publish`·`poll_metrics`·`read_stats`·`write_playbook` | 각 툴은 타입 시그니처 고정, 에이전트가 임의 부작용 못 냄 |
| FR-C3 | LLM 판단 계층 = Claude(`claude-sonnet-5`). 모델·시계·transport는 **주입식**(테스트에서 가짜 모델 대체 가능) | 가짜 모델로 한 사이클 결정론 재현 테스트 green |
| FR-C4 | LLM 산출 착지점은 **3곳으로 열거**(`content_item.body`·`playbook.guidance`·`analysis_note.body`). 그 외 수치/제어는 코드만 | 착지점 외 LLM 기록 경로 부재 테스트 |
| FR-C5 | 사이클 계획·위임은 Orchestrator가 수행, 각 서브에이전트 호출을 `run_event`로 관측 | 사이클 로그로 에이전트 흐름 재구성 가능 |

### 2.2 콘텐츠 생성 (FR-G)

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-G1 | Topic Agent가 개발자 주제 도메인에서 주제 발굴, `topic` 풀 + `topic_stats` 참조 | 주제가 `content_item.topic_id`로 추적 |
| FR-G2 | Content Agent가 주제 → 포맷별 산출물 생성: 피드=카드뉴스 문안, 릴스/쇼츠=영상 대본(장면·자막·나레이션) | format별 스키마 준수한 `media_spec` 생성 |
| FR-G3 | 콘텐츠는 발행 전 **결정론 렌더 스펙(`media_spec`)** 으로 확정 저장(LLM 재호출 없이 재현 가능) | 같은 content_item→같은 렌더 입력 |
| FR-G4 | **[신설 v2]** Topic Agent는 `research_trends` 툴로 **무료 외부 트렌드 소스**를 조회해 주제 발굴에 사용: Google Trends 급상승 RSS(무인증) · 네이버 검색 API(일 25,000회 무료) · 네이버 데이터랩(일 1,000회) · YouTube 인기영상(1unit/회) · GitHub 트렌딩/GeekNews RSS(개발 니치). 소스 일부 실패 시 조용히 제외하고 계속. **리서치로 확인 안 된 내용은 소재로 쓰지 않음**(프롬프트 규칙, 할루시네이션 방지) | 콜드 스타트 사이클에서 외부 소스 기반 topic 생성, 소스 1개 강제 실패 시에도 사이클 완주 |
| FR-G5 | **[신설 v2]** Content Agent는 **훅 문장을 본문과 분리 생성**하고 패턴 5종(bold_claim/curiosity/story/shock/question)을 `content_item.hook_pattern`에 기록 — FR-Q5 체크리스트 "훅" 항목의 측정 가능화 + 성과 분석 축 + 향후 밴딧 arm(FR-L3) | 발행 콘텐츠 전수가 hook_pattern 보유 |

### 2.4 콘텐츠 품질 게이트 (FR-Q) — 발행 전 하한 검증

> 근거: 템플릿 합성 콘텐츠의 시장 하한 미달이 프로젝트 성패에 직결(PLAN §10 리스크). 품질을 "학습으로 나중에 개선"에만 맡기지 않고 **발행 전 게이트**로 하한을 강제한다.

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-Q1 | **발행 전 자동 품질 검사**: 렌더된 `media_asset`이 게시되기 전 규격·가독성 하한을 통과해야 함(영상 9:16·길이 범위·오디오 존재/무음 아님, 카드 텍스트 오버플로우/최소 대비/필수 필드). 미통과=발행 차단 | 규격 위반 자산이 `publish_attempt`에 진입 못 함(차단 테스트) |
| FR-Q2 | 검사 결과를 `media_asset`에 기록(`quality_status`: passed/failed/needs_review, `quality_report`). 실패는 사유 원문 보존 | 실패 자산의 사유가 조회 가능 |
| FR-Q3 | **초기(Phase 0~1) 사람 검수 훅**: 자동 게이트가 성숙하기 전에는 `needs_review` 상태로 운영자 승인 후 발행하는 수동 관문을 옵션으로 제공(env 플래그). Phase 2부터 자동 게이트로 대체 가능 | 플래그 on 시 미승인 자산 발행 안 됨 |
| FR-Q4 | 품질 기준(임계값)은 **코드 상수/설정으로 외부화**(프롬프트가 아님) — 결정론 재검사 가능 | 같은 자산·같은 기준→같은 판정 |
| FR-Q5 | **정성 품질 하한(사람 정의)**: Phase 0 품질 스파이크에서 "발행 가능"의 정성 기준을 **체크리스트로 사전 확정**하고, 이후 `needs_review` 자동판정이 성숙하기 전까지 사람 검수(FR-Q3)가 이 체크리스트로 판정한다. 체크리스트는 **버전드 문서**로 보관 | Phase 1 발행 자산 전수가 체크리스트 항목별 pass/fail 기록을 가짐 |
| FR-Q6 | **Phase 0 정성 게이트의 정량 문턱**: 품질 스파이크는 **포맷별 최소 20 샘플**을 **리뷰어 2인 이상**이 독립 판정(판정이 갈리면 fail로 간주)하고, 포맷별 전항목-pass 비율 **≥ 60%**(초안, 스파이크에서 확정)를 "발행 가능 하한" 통과로 둔다. 미달 시 FR-Q 자동/사람 게이트를 Phase 1 필수로 승격([`PLAN.md` §9 Phase 0 ②](PLAN.md)) | 스파이크 리포트에 포맷별 표본수·통과율·리뷰어 수 기록, 미달 시 승격 이력 존재 |

**발행 가능 정성 체크리스트 (Phase 0 확정 · v1 초안).** FR-Q1~Q4는 규격 하한(9:16·길이·오버플로우·대비)만 잡는다 — 이는 *형식* 통과일 뿐, 시장 하한을 좌우하는 *실질* 품질(볼 이유가 있는가)은 잡지 못한다. 아래는 형식 통과 이후 사람이 판정하는 실질 기준이며, 항목·문턱은 Phase 0 스파이크에서 소수 샘플 검수로 확정해 이 문서의 버전으로 고정한다.

| 축 | 통과 기준(초안) | 판정 |
|---|---|---|
| **훅(첫 2초/첫 화면)** | 스크롤을 멈출 이유가 첫 프레임/카드 1장에 있는가 | pass/fail |
| **정보 밀도** | 개발자에게 "새로 알게 된 것" 1개 이상이 있는가(자명한 재탕 아님) | pass/fail |
| **가독 리듬** | 자막/나레이션 속도를 따라갈 수 있는가, 한 장면 과밀 아님 | pass/fail |
| **완성감** | 자동합성 티(어색한 TTS 끊김·빈 여백·깨진 정렬)가 "발행 못 할 수준"은 아님 | pass/fail |
| **CTA/마무리** | 끝맺음이 있는가(다음 행동·요약) | pass/fail |

> 전 항목 pass = 발행 가능. 1개라도 fail = `needs_review`(사람 승인 전 발행 차단). **판정 주체·정량 문턱(FR-Q6)**: Phase 0 스파이크는 포맷별 **최소 20 샘플**을 **리뷰어 2인 이상**이 독립 판정하고, 판정이 갈리면 fail로 간주(보수적)한다. 포맷별 전항목-pass 비율이 **≥ 60%**(초안, 스파이크에서 확정)면 "발행 가능 하한" 통과로 본다. 통과율이 낮으면 → **템플릿/대본 프롬프트 개선이 학습 루프보다 선행 과제**임을 뜻한다(품질을 "학습으로 나중에"에 미루지 않는다, [`PLAN.md` §9 Phase 0 ②·§10 리스크](PLAN.md)).

### 2.5 발행 (FR-P) — 공식 API만

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-P1 | **Instagram Graph API**로 피드 이미지 + 릴스 영상 발행(2단계: 컨테이너 생성→게시) | 실 계정에 실 post_id 반환 |
| FR-P2 | **YouTube Data API v3**로 쇼츠 영상 업로드(#Shorts, 세로 영상) | 실 채널에 실 video_id 반환 |
| FR-P3 | **멱등 발행 원장**(`publish_attempt` 상태머신): 재시작 시 이중 발행 0 | 크래시 3지점(pending/container/publish) 재시작 복구 테스트 |
| FR-P4 | 오류 분류: transient(재시도)/영구(토큰만료·한도) 구분, 미분류는 `error_raw` 원문 보존 | 한 채널 실패가 다른 채널 발행에 무영향(격리) |
| FR-P5 | **발행 한도 준수**: 채널별 API 쿼터/발행 한도를 스케줄러가 존중(초과 시 대기·스킵+알림). *현재 알려진 상한은 §7 참조, 구현 전 최신값 재확인* | 한도 근접 시 발행 지연·알림, 계정 차단 리스크 회피 |
| FR-P6 | **비용 하드 상한**: 사이클당 LLM/TTS/저장 호출 수·추정비용 상한을 코드 상수로 강제. 초과 시 발행 스킵+알림(계정·예산 폭주 방지). Phase 1의 최소 가드 → Phase 2에서 일 단위 예산으로 확장([`PLAN.md` §9](PLAN.md)) | 상한 초과 주입 시 발행 스킵·알림 테스트 |

### 2.6 반응 학습 (FR-L)

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-L1 | Analyst Agent가 발행 후 복수 시점에 인사이트 폴링 → `metric_observation`+`metric_value`. **결측=NULL**(0 금지). **[구체화 v2]** 폴링 시점 = 발행 후 **6h·24h·72h**(+이후 일 1회) — 시드 테스트→단계 확산이라는 플랫폼 공식 구조상 초기 곡선이 조기 판정 신호(FR-A3) | 미노출 지표가 NULL로 저장, CHECK 강제 |
| FR-L2 | `RewardFn(관측창)→float\|None`. goal별 산식, 데이터 부족/미확정=NULL(학습 제외). **[방향 확정 v2]** 산식은 **플랫폼 공식 신호와 같은 방향으로 정렬** — 완주 근사(avg_watch_time÷길이)·공유율(shares/reach)·YT `engagedViews/views` 중심 가중합, 조회수는 log 변환 보조(heavy-tail 방어). 계수는 M1 실측 후 사전등록(기존 원칙 유지) | reward NULL 행은 밴딧 집계에서 제외 |
| FR-L3 | `topic_stats`(주제×포맷×채널) 집계 → Growth Agent 밴딧이 다음 사이클 변형 선택. **선택은 루프 밖 결정론(시드 고정)**. **[활성 조건 명시 v2]** arm당 유효표본 ≥10 필요 — 계정당 일 1건×3주(≈20건)로는 통계 불성립. 따라서 **이번 라운드는 균등 탐색+플레이북만 사용**하고, 밴딧은 arm≤5(`hook_pattern` 5종)로 축소해 **발행 50건 축적 후 활성**(K2 폴백의 선제 적용) | 같은 시드·같은 통계→같은 선택 |
| FR-L4 | `playbook` 갱신(성과 요약·지침) → 다음 사이클 콘텐츠 생성에 참조 | 플레이북 버전 증가, 콘텐츠에 반영 |
| FR-L5 | **LLM 분석글(정직 귀인)**: 입력=DB 근거. 인과 주장은 근거 인용 가능할 때만, 불가하면 **"근거 부족" 명시**. 수치는 코드 계산, LLM은 서술만. 출력 검증기가 인용 없는 단정·실재하지 않는 post_id를 거부 | 검증기 거부 테스트, 지어낸 인용 0 |

### 2.7 웹 대시보드 / 운영 (FR-W) — **[개정 v2] W3·W4 필수, W1·W2 선택**

> 근거: 팀 요구사항 — 발행 성공/실패 알림(11), "크는/안 크는 이유" 인사이트 탭(12·13)은 필수 기능.

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-W1 | (선택) 채널 온보딩: IG 프로 계정/YouTube 채널 OAuth 연동, 토큰 **암호화 저장**, 검증 핑 | 검증 실패 시 연동 불가 |
| FR-W2 | (선택) 운영 설정: goal·발행 슬롯·주제 도메인·채널/포맷 on-off. 변경=새 국면(이력 보존·기저 재수집) | 변경 시 옛 데이터 불변 |
| FR-W3 | **[필수] 인사이트 탭**: 계정별 추이 차트+성장 기울기(자기 베이스라인 대비) + **auto vs hybrid 비교 4지표**(FR-E4) + 알고리즘 신호 스코어보드(FR-A1) + LLM 분석글(근거/뱃지) | 수치=코드, 분석글=근거 or "근거 부족" |
| FR-W4 | **[필수] 모니터링·알림 = Discord 웹훅**(무료, 구현 최소): 발행 성공/실패·토큰 만료·한도 초과·품질 게이트 차단을 통지. 실패 알림 = **오류 분류**(auth/quota/spam_block/transient/render) + 원문 + **LLM 원인 분석 1줄**(LLM 호출 실패 시 분류명만이라도 발송). 발신 지점 = Publisher 실패 처리부 + 사이클 최상위 catch. 모든 알림은 DB에도 적재(웹 알림 로그와 이중화) | 강제 실패 주입 시 웹훅 수신 + DB 기록 |

### 2.8 실험 운영 (FR-E) — **[신설 v2]** 계정 4개, auto vs hybrid

> 근거: 팀 요구사항 6 — SNS당 2계정, 완전자동 vs AI+사람 비교가 프로젝트의 핵심 실험. FR-Q3의 사람 검수 관문을 채널 단위 mode로 승격하면 기존 설계 재사용으로 실험 장치가 완성된다.

## 5. 성공 기준 (DoD)

1. **M1(실환경 관통)**: IG 피드 1건 + IG 릴스 1건 + YouTube 쇼츠 1건을 딥에이전트가 자동 발행 → 실 post_id/video_id 확보 → 지표 폴링 → reward 산출 → 리포트/분석글 열람까지 **한 번 관통**.
2. 밴딧 학습 루프가 `topic_stats`/`playbook`을 갱신하고 다음 사이클 선택에 반영됨(결정론 재현).
3. 결정론·멱등·결측=NULL·정직귀인 테스트가 CI(GitHub Actions)에서 green.
4. Docker Compose로 전 서비스가 단일 호스트에서 구동.
5. **[추가 v2]** 계정 4개(auto×2, hybrid×2) 전부에서 발행이 관통되고, hybrid 승인 관문(FR-E1)·Discord 알림(FR-W4)·auto vs hybrid 비교 리포트(FR-E4)가 작동.

위 1~4는 **엔지니어링 완료(build) 기준**이다. 아래 §5.1은 **제품 성공(outcome) 기준**으로, 자율 루프가 실제로 성장을 만드는지를 판단한다.

### 5.1 제품 성공지표 (측정 계획)

> 절대 수치 목표는 채널·주제·시작 시점에 따라 편차가 크므로 **자기 베이스라인 대비 상대 개선**으로 정의한다(NFR-5). 임계값은 M1 실측으로 사전등록(pre-register)한 뒤 고정한다 — 사후에 목표를 맞추지 않는다(정직 귀인, NFR-6).

| # | 지표 | 정의 | 목표(사전등록 대상) | 판정 시점 |
|---|---|---|---|---|
| S1 | **성장 기울기 > 0** | goal 지표(조회수 등)의 시간축 회귀 기울기가 자기 베이스라인 대비 유의하게 양(+) | 관측창 누적 후 기울기 신뢰구간 하한 > 0 | Phase 2 누적 N사이클 후 |
| S2 | **운영자 개입 시간** | 사이클당 사람이 손대는 시간(승인·수정·수동 발행 포함) | 수동 운영 대비 대폭 감소(목표치 M1 후 확정) | Phase 2 |
| S3 | **무인 발행 성공률** | 사람 개입 없이 기획→발행 완주한 사이클 비율 | 사전등록 하한 이상 | Phase 2 |
| S4 | **품질 게이트 통과율**(FR-Q) | 발행 시도 중 품질 하한 통과 비율 | 사전등록 하한 이상, 하락 추세 없음 | Phase 1~ |
| S5 | **사이클당 비용** | LLM+TTS+저장 등 1사이클 총비용 | 비용 상한(cost cap) 이내 | Phase 2 |

**측정 원칙**: S1~S5의 수치는 전부 **코드가 DB(`metric_*`·`reward`·`run_event`·`media_asset`)에서 집계**하고, LLM은 서술만 한다(FR-L5). 표본 부족·관측창 미완은 목표 미달이 아니라 **판정 보류(NULL)** 로 처리한다(FR-L2). 목표치 자체는 M1 관통(§5-1) 실측 분포를 보고 팀이 사전등록한다 → §6 미결정 항목.

### 5.2 중단 · 피벗 판정선 (kill criteria)

> 성공지표(S1~S5)의 목표치는 pre-register 대상이라 지금 고정하지 않는다. 그러나 **"성공이 아니면 계속한다"의 무한루프를 막기 위해**, 목표치와 별개로 *실패를 인정하는 규칙*은 착수 전에 정한다. 아래는 규칙의 형태를 고정하고, 문턱(N·평가창 수)만 M1 후 채운다.

| ID | 판정선 | 규칙(형태 고정, 문턱=pre-register) | 조치 |
|---|---|---|---|
| K1 | **성장 무신호** | Phase 2 누적 N사이클 후, S1(성장 기울기) 신뢰구간 하한이 **연속 2개 평가창에서 ≤ 0** | 자율 루프 중단 → 콘텐츠 품질/주제 전략 재설계(피벗) |
| K2 | **학습 무효** | 밴딧 도입 후 M개 평가창 동안 arm별 유효표본(reward≠NULL)이 학습 성립 하한 미달 | 밴딧 비활성 → **고정 플레이북**으로 폴백(학습 루프는 관측만) |
| K3 | **품질 붕괴** | S4(품질 게이트 통과율)가 하락 추세이거나 사전등록 하한 미달 지속 | 발행 중단 → 템플릿/대본 개선 우선 |
| K4 | **비용 초과** | S5(사이클당 비용)가 cost cap(FR-P6)을 반복 초과 | 자율 발행 중단, 원인 규명 전 재개 금지 |

**정직 원칙(NFR-6 연장).** K1~K4 발동은 "실패"가 아니라 **가설([`PLAN.md` §2](PLAN.md) 수요 가설)이 이 라운드에서 기각됨**을 뜻한다. 발동 시 결과를 그대로 기록하고 확장(PLAN §9 Phase 4)을 보류한다. 문턱값(N·M·하한)은 §6 미결정으로 이관해 M1 실측 후 pre-register 한다.

## 7. 외부 제약 (구현 전 최신값 재확인)

- **Instagram Graph API**: 프로페셔널(비즈니스/크리에이터) 계정 + 연결된 Facebook 페이지 필요. 콘텐츠 게시 API는 2단계(미디어 컨테이너→게시). 계정당 24시간 발행 한도 존재(과거 25건 기준). 릴스는 동영상 컨테이너로 발행.
- **YouTube Data API v3**: `videos.insert` 업로드는 쿼터 비용이 큼(과거 기준 1회 ~1600 units, 일 기본 쿼터 10,000 units → 하루 수 건 규모). 쇼츠는 세로 영상 + #Shorts.
- **Meta/Google 심사**: 자기 계정 운영 범위를 넘어 타인 계정 대상 서비스로 확장 시 앱 검수(App Review) 게이트 발생 — 이번 범위(자기/팀 채널) 밖.
- **[최신화 v2]** 릴스 최대 3분(2025-01, 단 3분 초과분은 신규 시청자 추천 제외 관찰) · 쇼츠 최대 3분(2024-10) · **YT 조회수 집계 변경(2025-03)**: `views`=재생 시작 집계, `engagedViews`=의미 있는 시청(수익화·YPP 기준은 engagedViews) · 인스타 어그리게이터 억제(2024-04~): 30일 내 무편집 재게시 10회↑ 계정은 추천 제외 · IG 인사이트 메트릭 다수 개편(v22: `plays`·`impressions` deprecated → `views` 통일).
- 위 수치는 정책 변동이 잦으므로 **구현 착수 시 공식 문서로 재확인**한다.
