## 1. 한 줄 정의

**개발자 주제 콘텐츠**를 **IG 피드 게시물 · IG 릴스 · YouTube 쇼츠**에 **딥에이전트가 자동으로 기획·제작·발행**하고, **반응(지표)을 학습**해 **채널을 키우는** 멀티에이전트 자율 성장 엔진. **[v2]** 인스타·유튜브 각 2계정을 **완전자동(auto) vs AI+사람(hybrid)**로 나눠 "계정이 크는/안 크는 이유"의 인사이트를 도출한다.

## 2. 배경 · 목표

**누구의 어떤 고통인가.** 기술 브랜딩을 원하는 개발자/소규모 팀은 콘텐츠의 가치는 알지만 **꾸준한 발행을 지속하지 못한다.** 주제 발굴 → 대본/카드 제작 → 채널별 규격 맞춤 → 발행 → 반응 분석 → 다음 개선의 루프가 매 사이클 수십 분~수 시간의 반복 노동을 요구하고, 본업(개발)에 밀려 채널이 방치되기 때문이다. 즉 **1회성 제작이 아니라 "지속"이 병목**이다.

**기존 수단 대비 차별점.**

| 대안 | 한계 | 본 프로젝트의 차별 |
|---|---|---|
| 수동 운영 | 지속 불가(본업에 밀림), 분석·학습이 감(感) | 루프 전체 무인 자동화 + 반응 기반 학습 |
| Buffer/Hootsuite 등 예약 발행 툴 | **예약만** 대신, 콘텐츠 제작·주제 선택·개선은 사람 | 제작·선택·개선까지 에이전트가 수행 |
| 단발 생성형 콘텐츠 툴 | 1회성 생성, 반응을 다음 콘텐츠에 되먹이지 않음 | 지표→reward→학습으로 **채널이 스스로 학습** |

**전제(수요 가설).** 위는 검증된 시장 데이터가 아니라 **팀의 관찰 기반 가설**이다. 실환경 관통으로 "지속 자동화가 실제로 성장 기울기를 만드는가"를 먼저 자기 검증한 뒤 확장 여부를 판단한다. 착수 전 **경량 수요 벤치마크**([13-로드맵·리스크](plan/13-로드맵-리스크.md) Phase 0 ③)로 유사 개발자 채널의 공개 성장 사례 소수를 수집해, S1 성공지표 목표치 사전등록의 사전분포 근거로 남긴다.

**목표.**
- 개발자 브랜딩/채널 성장의 반복 루프(주제 발굴 → 콘텐츠 제작 → 멀티채널 발행 → 반응 수집 → 학습 → 개선)를 **자율 에이전트 루프**로 무인 자동화한다.
- **[v2]** auto vs hybrid 계정 비교에서 2~3주 내 **유의미한 인사이트**를 도출한다 ([01-실험설계](plan/01-실험설계.md)).
- **핵심 성과 지표**: 자기 채널의 시간에 따른 성장 기울기(타 계정 절대 비교 금지). 정량 목표·측정은 §4 참조.

## 3. 개발 원칙 (팀 공통)

1. **공식 API만** — 비공식 스크래핑/자동화 금지(계정 정지 리스크).
2. **결정론 재현** — 모델·시계·transport 주입, 시드 고정. 가짜 모델로 사이클 재현 테스트.
3. **멱등 발행** — 이중 발행 0(상태머신 + 재시작 복구).
4. **missing=NULL** — 지표 결측을 0으로 채우지 않음(DB CHECK 강제).
5. **정직 귀인** — LLM 분석글은 근거 있을 때만 인과 주장, 없으면 "근거 부족". 수치는 코드만.
6. **자기 베이스라인 성장만** — 타 계정 절대 비교 금지, 한계 정직 표기.
7. **시크릿 암호화** — 토큰 평문 저장 금지.
8. **thin spec** — 경계·데이터·측정만 고정, 에이전트 내부 행동은 프롬프트/플레이북에.

## 4. 성공 기준

### 4.1 엔지니어링 완료 (DoD)

1. **실환경 관통**: IG 피드 1건 + IG 릴스 1건 + YouTube 쇼츠 1건을 딥에이전트가 자동 발행 → 실 post_id/video_id 확보 → 지표 폴링 → reward 산출 → 리포트/분석글 열람까지 **한 번 관통**.
2. 학습 루프가 `topic_stats`/`playbook`을 갱신하고 다음 사이클 선택에 반영됨(결정론 재현).
3. 결정론·멱등·결측=NULL·정직귀인 테스트가 CI(GitHub Actions)에서 green.
4. Docker Compose로 전 서비스가 단일 호스트에서 구동.
5. **[추가 v2]** 계정 4개(auto×2, hybrid×2) 전부에서 발행이 관통되고, hybrid 승인 관문·Discord 알림·auto vs hybrid 비교 리포트가 작동.

### 4.2 제품 성공지표 (사전등록 대상)

> 절대 수치 목표는 편차가 크므로 **자기 베이스라인 대비 상대 개선**으로 정의. 임계값은 M1 실측으로 사전등록 후 고정 — 사후에 목표를 맞추지 않는다.

| # | 지표 | 정의 | 목표(사전등록 대상) | 판정 시점 |
|---|---|---|---|---|
| S1 | **성장 기울기 > 0** | goal 지표의 시간축 회귀 기울기가 자기 베이스라인 대비 유의하게 양(+) | 신뢰구간 하한 > 0 | **[v2] 프로젝트 종료 후 관측 지속 항목** |
| S2 | **운영자 개입 시간** | 사이클당 사람이 손대는 시간 | 수동 운영 대비 대폭 감소 | Phase 2 |
| S3 | **무인 발행 성공률** | 사람 개입 없이 기획→발행 완주한 사이클 비율(auto 계정) | 사전등록 하한 이상 | Phase 2 |
| S4 | **품질 게이트 통과율** | 발행 시도 중 품질 하한 통과 비율 | 사전등록 하한 이상, 하락 추세 없음 | Phase 1~ |
| S5 | **사이클당 비용** | LLM+TTS+저장 총비용 | cost cap 이내 | Phase 2 |

**측정 원칙**: S1~S5 수치는 전부 코드가 DB에서 집계, LLM은 서술만. 표본 부족은 목표 미달이 아니라 **판정 보류(NULL)**.

### 4.3 중단·피벗 판정선 (kill criteria)

> 목표치와 별개로 *실패를 인정하는 규칙*은 착수 전에 정한다. 문턱(N·평가창)은 M1 후 사전등록. **[v2] 이번 라운드는 기간상 K1 판정 불가 → K2~K4만 활성.**

| ID | 판정선 | 규칙(형태 고정) | 조치 |
|---|---|---|---|
| K1 | 성장 무신호 | S1 신뢰구간 하한이 연속 2개 평가창 ≤ 0 | 자율 루프 중단 → 전략 재설계 (이번 라운드 비활성) |
| K2 | 학습 무효 | 밴딧 도입 후 arm별 유효표본이 학습 하한 미달 | 밴딧 비활성 → 고정 플레이북 폴백 |
| K3 | 품질 붕괴 | S4 하락 추세 또는 하한 미달 지속 | 발행 중단 → 템플릿/대본 개선 우선 |
| K4 | 비용 초과 | S5가 cost cap 반복 초과 | 자율 발행 중단, 원인 규명 전 재개 금지 |

**정직 원칙**: K 발동은 "실패"가 아니라 수요 가설이 이 라운드에서 기각됨을 뜻한다. 결과를 그대로 기록하고 확장을 보류한다.
