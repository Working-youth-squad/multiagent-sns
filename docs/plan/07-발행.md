## 2. 멱등 발행 상태머신 (`publish_attempt`)

```
pending → container_created → published
   │              │
   └──────────────┴──────────→ failed
```

- 발행 진입 전 `publication.status` 확인(published면 재발행 스킵) → **크래시 재시작 시 이중 발행 0**.
- **발행 진입 전 품질 게이트 확인**: `media_asset.quality_status = passed`가 아니면 `pending`으로 진입하지 않음([05](05-콘텐츠생성-품질게이트.md) FR-Q). 예외 없음 — 사람이 우회 승인하는 경로는 없다.
- IG는 2단계(미디어 컨테이너 생성 → 게시)라 중간 상태 `container_created`가 필요 — 컨테이너 ID 보존으로 재시작 시 재사용.
- 영구 오류(토큰 만료·한도 초과)는 `error_raw`에 원문 보존, 채널 격리(다른 채널 발행 계속).
- 실패·성공 모두 Discord 알림([10](10-웹-알림.md) FR-W4).

## 3. 계정 안전 운영 (NFR-10 실행 수칙)

- 공식 API만(비공식 자동화 금지) · 계정 개설 후 워밍업(프로필 완성, 초기 저빈도) · 보수적 발행 빈도(일 1건, 코드 상수) · 발행 시각 지터(기계적 정시 패턴 회피) · 한도 근접 시 자동 대기.
- 콘텐츠 측 안전(비진정성·비독창 판정 방어)은 NFR-11([12](12-비기능-테스트.md)) + FR-A2([09](09-알고리즘-신호-최적화.md)).
