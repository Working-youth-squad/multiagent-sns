# 06. 지표 수집·인사이트

> 담당 역할: **역할 B (콘텐츠·에이전트)** · 관련 요구사항: 4, 12, 13 · 상위 문서: [기획서 총괄](../기획서.md)
> 이식 기반: feedr-clone `analytics-sync` + 인사이트 화면의 auto vs approve 비교 박스

## 1. 지표 수집 (analytics-sync.yml — 매일 1회, 요구사항 4)

| 플랫폼 | 계정 단위 | 게시물 단위 |
|---|---|---|
| YouTube | `channels?part=statistics` (구독자·총조회) | 가능 시 YouTube Analytics API — 시청 지속시간 (OAuth scope 추가, 2주차 여유 시) |
| Instagram | `GET /{ig-user-id}/insights?metric=follower_count,reach&period=day` | `GET /{media-id}/insights?metric=views,reach,likes,comments,saved,shares` |

- 계정 단위 → `analytics_snapshots`(채널×일 1행), 게시물 단위 → `post_insights`(게시물×일)
- **결측=NULL 원칙**: 신규 게시물의 지표 미노출 구간을 0으로 채우지 않는다 ([02-데이터모델](02-데이터모델.md) §3)
- **알고리즘 신호 지표 확장**: 플랫폼 공식 랭킹 신호와 대응하는 메트릭(IG: reach·shares·saved·avg_watch_time·skip_rate / YT: engagedViews·avg_view_percentage·subscribersGained)을 수집하고, 발행 직후 6·24·72h 다회 폴링으로 초기 확산 곡선을 확보 — 상세와 근거는 [09-알고리즘-신호-최적화](09-알고리즘-신호-최적화.md)

## 2. reward 산출과 학습 연결 (요구사항 5)

- 발행 후 관측창(예: 72시간) 지표로 게시물별 reward를 **코드가** 산출 (예: 조회수 정규화 + 참여율 가중 — 산식은 1주차 실측 후 확정)
- 데이터 부족 시 reward=NULL → 학습에서 제외 (지어내지 않음)
- reward → Reflexion 교훈·플레이북 갱신([03-딥에이전트](03-딥에이전트-트렌드조사.md) §2) → 다음 사이클의 주제·훅·시간 선택에 반영

## 3. 인사이트 탭 데이터 (요구사항 12·13)

**수치 — 전부 코드가 계산** (화면 명세는 [07-웹화면](07-웹화면.md) §4):

- 계정별 팔로워/조회/참여율 시계열 + **성장 기울기**(최소자승 회귀)
- **auto vs hybrid 비교 4지표**: 글당 조회·좋아요·참여율·팔로워 증가 (feedr-clone 비교 박스 계승 — 이 실험의 핵심 산출물)
- 발행 성공률(S1), 훅 패턴별 성과, 발행 시간대별 성과
- 사이클당 비용(S4 — `autopilot_runs.cost_estimate` 집계)

**분석글 — LLM이 서술** (주 1회, `insight_reports`):

- "이 계정이 크는/안 크는 이유"를 DB 수치를 근거로 서술
- **규칙**: ① 인용 수치는 코드가 넘겨준 집계값(`figures` JSON)에서만 ② 근거 없는 인과 주장은 "근거 부족"으로 표기 ③ 출력 검증 — 분석글의 수치가 figures와 불일치하면 거부·재생성
- 2~3주 표본 한계를 감안해 단정 대신 관찰("hybrid 계정의 훅 수정이 조회수와 동행함") 중심으로
