# 01. 실험 설계 · 범위

> 상위: [PLAN.md](../PLAN.md) · 관련: [08-지표-학습](08-지표-학습.md), [10-웹-알림](10-웹-알림.md)

## 1. 실험 설계 — 변수는 mode 하나 [신설 v2 · 3모드 확장 v4]

> 근거: 팀 요구 — SNS당 2계정, 완전자동 vs AI+사람 비교. 2~3주 안에 "계정이 크는/안 크는 이유"의 유의미한 인사이트를 내려면 자기 실험군-대조군 비교가 유일하게 성립하는 설계다.
>
> **[신설 v4] 발행 모드 3분류** — 결론 문장은 "같은 프롬프트(주제)를 넣었을 때 수동/반자동/자동 중 무엇이 가장 효과적이었다"이다. 이를 위해 기존 auto·hybrid에 `manual`(수동)을 더해 3분류로 확정한다. 분류 정본은 `sns/publish/modes.py`.

| 계정 | 플랫폼 | 모드 | 운영 방식 |
|---|---|---|---|
| IG-A | Instagram | `auto` (자동) | 기획→제작→검수→발행 전 과정 무인 |
| IG-B | Instagram | `hybrid` (반자동) | 에이전트가 주제 3~5개 제안·초안 생성 → 사람이 선택·수정·승인 후 발행 |
| IG-M | Instagram | `manual` (수동) | **[신설 v4]** 사람이 같은 주제(프롬프트)를 배정받아 직접 작성·앱에서 직접 발행 → 시스템에는 `external_post_id`만 등록 |
| YT-A | YouTube | `auto` | 〃 (쇼츠) |
| YT-B | YouTube | `hybrid` | 〃 (쇼츠) |
| YT-M | YouTube | `manual` | 〃 (쇼츠, 수동 운영 여력에 따라 선택 — 최소 IG-M은 운영) |

**통제 변수** — 동일 주제 도메인·발행 슬롯·템플릿 풀·발행 빈도(일 1건). 차이는 채널 `mode` 하나만 둔다. manual도 **사이클이 배정한 같은 주제**를 받는다(주제는 사이클당 1건 공유).

### 기능 요구사항 (FR-E)

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-E1 | 채널 단위 `mode(auto\|hybrid\|manual\|off)` **[v4: manual 추가]**. **auto**=전 과정 무인. **hybrid**=주제 제안→사람 선택, 초안은 needs_review 관문([05](05-콘텐츠생성-품질게이트.md) FR-Q3)에서 사람 승인·수정 후 발행. **manual**=사이클은 주제 배정만(콘텐츠 생성·기계 발행 없음), 사람이 직접 작성·발행. `off`=발행 중지(실험 모드 아님) | mode별 사이클 흐름 분기 테스트 |
| FR-E2 | 통제 변수: 동일 주제 도메인·발행 슬롯·템플릿 풀·발행 빈도(일 1건). 차이는 mode 하나. **[신설 v3] 콜드 스타트 시딩 규칙**: 첫 사이클은 **프롬프트/주제만 통일하고 결과물은 계정별 독립 생성**(동일 완성본 복붙 아님) — auto vs hybrid 차이를 첫 사이클부터 관측하기 위함 | 채널 간 설정 diff = mode뿐, 첫 사이클 콘텐츠는 계정별 독립 산출 |
| FR-E3 | 사람 개입 기록: hybrid에서 주제 선택·초안 수정 시 `content_item.edited_by_human=true` — "사람이 고치면 성과가 달라지는가" 분석 축 | hybrid 수정 콘텐츠 전수 기록 |
| FR-E4 | 비교 리포트: **auto vs hybrid vs manual 3모드 [v4]** — **4지표**(글당 조회·좋아요·참여율·팔로워 증가)를 플랫폼별 산출(수치=코드) → 인사이트 탭([10](10-웹-알림.md) FR-W3) 표시. 비교 축의 단일 출처는 `publication.mode` 스냅샷(채널 mode 변경에도 발행 시점 모드 보존) | 표본 부족 시 판정 보류(NULL) 표기 |
| FR-E5 | **[신설 v4] 수동 발행 + ID 등록 경계**: manual 채널은 기계 발행 경로(발행 러너)에 절대 진입하지 않는다. 사람이 발행한 게시물은 `register_manual_publication`으로 등록 — `content_item`(사람 본문, `edited_by_human=true`) + `publication(status=published, mode=manual, external_post_id)` 생성, (채널, external_post_id) 멱등. 등록된 행부터는 지표 수집·보상이 기계 발행 건과 동일 경로 | manual 채널 발행 러너 미선택 테스트 + 등록 멱등 테스트, auto/hybrid 채널에 수동 등록 시 거부(실험군 오염 차단) |

## 2. 범위

**포함(이번 라운드)**
- 채널: IG 피드(카드뉴스 이미지) · IG 릴스(영상) · YouTube 쇼츠(영상) — **전부 공식 API**.
- 실험 설계: 위 §1 (계정 4개, auto vs hybrid).
- 주제 발굴 입력: **무료 외부 트렌드 소스** ([04-트렌드조사](04-트렌드조사.md)) — 내부 `topic_stats`만으로는 콜드 스타트 시 주제 발굴 경로가 없다.
- 영상: **템플릿 코드 합성**(자막+슬라이드+TTS). 렌더러는 Phase 0 품질 스파이크에서 확정 ([06-미디어렌더](06-미디어렌더.md)). 생성형 비디오 모델 미사용.
- 코어: **deepagents 프레임워크 그대로 도입** ([03-멀티에이전트](03-멀티에이전트.md)).
- 학습: 플레이북 갱신 + LLM 분석글(정직 귀인) + 알고리즘 공식 신호 스코어보드([09](09-알고리즘-신호-최적화.md)). 밴딧은 표본 축적 후 활성([08](08-지표-학습.md) FR-L3).
- 운영: 스케줄 실행(인프라는 [02](02-아키텍처-스택.md)·1주차 확정) + PostgreSQL + Docker Compose + GitHub Actions CI. 웹은 **알림·인사이트 탭 필수**([10](10-웹-알림.md)), 나머지 선택.
- 대상: **팀 소유 실험 계정 4개** (타인 계정 대행 없음).

**미포함(후속)**
- 다중 사용자 SaaS(다중테넌트)·타인 계정 대행 → Meta/Google App Review 게이트 발생, 이번 범위 밖.
- TikTok 등 추가 채널, 생성형 비디오, 실시간 라이브.
- **[신설 v3] Threads** — 이전 프로젝트에 발행 자산이 있으나, 이번 라운드는 IG·YT 4계정 통제 설계(변수=mode 하나) 유지를 위해 **후속으로 분리**. 텍스트 채널이라 완전자동 난이도가 낮아 확장 1순위 후보로 기록.
- **[신설 v3] 생성형 영상 툴**(Higgsfield·Runway·Sora 류) — 결정론·재현성·비용 상한과 상충, 콘텐츠 정책 리스크. 품질이 병목으로 확정되면 별도 스파이크로 재평가([06](06-미디어렌더.md) §5).
