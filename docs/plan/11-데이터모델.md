# 11. 데이터 모델 (ERD)

> 상위: [PLAN.md](../PLAN.md) · DB: PostgreSQL 단일 인스턴스 · 다이어그램: [diagrams/erd.mermaid](../diagrams/erd.mermaid)
> 설계 원칙: **정규화 + CHECK 물리 강제 + 지표 결측=NULL + append-only 이벤트**. (구 ERD.md 전체 내용 + v2 개정을 이관)

## 1. 테이블 목록 (15)

| 테이블 | 역할 | 핵심 불변식(CHECK) |
|---|---|---|
| `channel` | 발행 채널(IG/YouTube) + 암호화 토큰 + **운영 모드 [v2]** | platform·status enum, **mode enum(auto/hybrid/off) — 실험 변수(FR-E1)**, 토큰 평문 저장 금지 |
| `cycle` | 발행 사이클(계획 단위) | status enum |
| `topic` | 개발자 주제 풀 | status enum |
| `topic_stats` | 주제×포맷×채널 성과 집계(밴딧 입력) | (topic_id, format, platform) 유일 |
| `content_item` | 생성 콘텐츠(대본/카피/문안 + 렌더 스펙) + **훅 패턴·사람 개입 [v2]** | format·status enum, **hook_pattern enum(bold_claim/curiosity/story/shock/question — FR-G5)**, **edited_by_human bool(FR-E3)** |
| `media_asset` | 렌더된 미디어 + checksum + 품질게이트 결과 | kind enum, quality_status enum(passed/failed/needs_review) |
| `publication` | 채널 발행 기록 | status enum |
| `publish_attempt` | 멱등 발행 상태머신 | state enum, 이중발행 차단 |
| `metric_observation` | 지표 관측 시점 | window_index — **[확정 v2] 6h·24h·72h(+이후 일 1회), FR-A3 입력** |
| `metric_value` | 지표 값 | **missing XOR value** CHECK (§3) |
| `reward` | 사이클/게시물 보상 | reward_value NULL 허용(학습 제외) |
| `playbook` | 학습된 지침 요약 | scope enum |
| `analysis_note` | LLM 분석글(정직 귀인) | insufficient_evidence 플래그 |
| `run_event` | 실행 이벤트 로그(비용 포함) | kind enum, append-only |
| `schema_version` | 마이그레이션 버전 | 전진 순번 |

## 2. 핵심 관계

- `channel 1─* publication` : 한 채널이 여러 게시물을 발행.
- `content_item 1─* publication` : 한 콘텐츠를 여러 채널에 교차 발행 가능(같은 영상 → IG 릴스 + YT 쇼츠). 채널별 발행 행 분리.
- `content_item 1─* media_asset` : 콘텐츠 1개가 이미지/영상/썸네일 등 복수 산출물.
- `cycle 1─* content_item` · `topic 1─* content_item` · `topic 1─* topic_stats`.
- `publication 1─1 publish_attempt` : 멱등 발행 상태머신(재시작 복구 지점).
- `publication 1─* metric_observation 1─* metric_value` : 시점별·지표별 정규화 저장.
- `publication 1─0..1 reward` : 관측 창 완료 시 보상 산출(미확정=NULL).

## 3. 결측 처리 (핵심 규칙)

`metric_value`는 **`missing=true`이면 `value IS NULL`, `missing=false`이면 `value IS NOT NULL`**를 CHECK로 강제한다. 지표를 0으로 채우지 않는다 — 플랫폼이 값을 노출하지 않은 것과 실제 0을 구분해야 학습·리포트가 왜곡되지 않는다.

```sql
CONSTRAINT metric_missing_xor
  CHECK ( (missing AND value IS NULL) OR (NOT missing AND value IS NOT NULL) )
```

## 4. 수집 메트릭 표준 (metric_value.metric_key) — [신설 v2, FR-A1 근거]

플랫폼 공식 랭킹 신호와 1:1 대응하는 메트릭을 수집한다 (정확한 API 메트릭명 기준):

| 플랫폼 | metric_key | 원본 API 메트릭 | 대응 신호 |
|---|---|---|---|
| IG | reach / likes / shares / saved / comments | media insights 동명 | likes·**sends**·saves per reach |
| IG | avg_watch_time_ms | `ig_reels_avg_watch_time` (ms) | watch time — 완주 근사 = ÷영상 길이 |
| IG | skip_rate | `reels_skip_rate` (도입 중, 가용 시) | 첫 3초 훅 통과 |
| IG | views | `views` (v22 통일 — plays·impressions deprecated) | 도달·재생 |
| YT | views / engaged_views | `views`, `engagedViews` | **viewed vs swiped away 근사 = engagedViews÷views** |
| YT | avg_view_duration_s / avg_view_pct | `averageViewDuration`, `averageViewPercentage` | 시청 지속 |
| YT | likes / comments / shares / subscribers_gained | Analytics API 동명 | 참여·구독 전환 |

주의: YT Studio의 "Viewed vs swiped away" 정확 수치·시청 후 설문은 API 미제공(근사만 가능). 결측=NULL 원칙 동일 적용.

## 5. LLM 착지점 (제어 채널 분리)

LLM이 기록할 수 있는 테이블은 **열거된 3곳뿐**이다. 그 외 제어 흐름/수치 컬럼은 코드만 기록한다.

1. `content_item.body` — 대본/카피/문안
2. `playbook.guidance` — 성과 요약/지침(서술)
3. `analysis_note.body` — 성과 분석글(서술, 수치 재계산 금지)

## 6. 마이그레이션 정책

- `schema_version` 전진 순번(정수 또는 타임스탬프 파일명), 트랜잭션 원자성.
- 되돌림은 forward migration(drop/alter)로 처리. 스키마 스냅샷은 CI에서 검증.

## 7. 미결정 (구현 착수 전 확정)

| 항목 | 비고 |
|---|---|
| ~~PK 타입(UUID vs bigint identity)~~ | **[확정 T0-2]** UUID (`gen_random_uuid()`) — 이 규모에서 성능 차이 무의미, 외부 노출 안전 |
| ~~ORM(raw asyncpg vs SQLAlchemy)~~ | **[확정 T0-2]** raw SQL 마이그레이션 + psycopg 직접 사용(동기). 쿼리 복잡도가 커지면 **SQLAlchemy Core(쿼리 빌더만) 추가 가능** — 마이그레이션 방식은 불변 |
