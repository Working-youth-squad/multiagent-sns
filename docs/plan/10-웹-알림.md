## 3. hybrid 승인 화면 (FR-E1·FR-Q3의 UI 접점)

- 주제 제안 3~5개 중 선택 → 초안(대본·미리보기) 확인 → 인라인 수정(제목/대본/발행시각) → 승인/반려. 수정 시 `edited_by_human=true` 기록.
- **[신설 v3] 수동 프롬프트 시드 입력(FR-W5)**: 제안 목록 대신 사람이 직접 주제/프롬프트를 입력하는 진입점. 입력 → 초안 생성 후 위와 동일한 승인 흐름으로 합류. 시드 발행분도 `edited_by_human=true`.

## 4. 키워드 챗봇 (FR-W6 상세)

구현: `sns/chat/`(대화 계층) + `sns/web/chat/`(화면) + `scripts/run_chat_web.py`(:8003).
프리뷰는 `scripts/preview_chat_web.py` — DB·API 키 없이 실제 키워드 조회까지 돈다.

### 4.1 구조 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 화면 | 폼 POST + 전체 새로고침, JS 0줄 | `web/approve`·`web/onboarding`과 같은 규율(템플릿 엔진·빌드 단계 없음). 새 답변으로 내려가는 것은 `#bottom` 앵커가 한다 |
| 멀티턴 상태 | **서버가 소유**(DB). hidden input으로 이력을 실어 나르지 않는다 | 요청이 턴마다 커지고, 클라이언트가 이력을 고칠 수 있다. 온보딩 위저드(stateless)와 갈리는 지점 |
| 영속 | `chat_conversation` + `chat_message`, append-only | 대화가 발행물의 근거다 — 어떤 랭킹을 보고 무엇을 확정했는지 사슬이 끊기면 안 된다 |
| LLM | **필수**(대화가 본체) | 온보딩의 탈부착 협력자들과 다른 점. 거기선 인터뷰 완주가 본체였다. 프로바이더는 env `SNS_MODEL_PROVIDER`(`gemini` 기본 / `openai`) — [sns.agents.models] |
| 콘텐츠 제작 | 별도 스레드. 대화에는 `system` 메시지로 진행·결과 | 동기로 완주시키면 폼 POST가 분 단위로 멈춘다(실측 337초) |
| 초안 표시 | 만들어진 본문·카드 이미지를 **대화에 카드로** 보여주고 승인 화면으로 링크 | 문장만으로는 무엇이 나올지 모른 채 승인 화면으로 건너가야 한다. 페이로드 계약 = [sns.chat.drafts] |
| 이미지 | `GET /media/{asset_id}` 중계. **id로만 받는다** | 렌더 산출은 `file://` URI라 브라우저가 직접 못 읽는다. 저장소 URL을 쿼리로 받으면 그 라우트가 임의 파일 읽기 통로가 된다 |
| 초안 뱃지 | 주 뱃지는 `content_item.status`(승인 상태) | `media.quality_status=passed`여도 사람 승인 전이면 안 나간다 — 품질만 보이면 발행된 줄 안다 |
| 발행 모드 | hybrid 채널만 | FR-W5 규정(auto는 스케줄 트리거 유지) |

### 4.2 랭킹 수치는 LLM을 거치지 않는다

`search_keywords` 툴이 `rank_keywords` 결과 **전량**을 코드로 포착해 원본 그대로 저장하고
(`role='ranking'`, `ranking_to_dict` 산출), 화면이 그 원본에서 표를 그린다.
LLM에게 돌려주는 문자열은 **수치가 빠진** 요약(키워드 이름 + 소스 수 + 필터 상태 문장)이다.

관측된 실패 양식 때문이다 — `rank_std=None`("소스 1곳뿐이라 불일치를 잴 수 없다")을 LLM은
"0.00, 완전 일치"로 옮겨 적는다. 두 사실은 정반대다. 숫자를 손에 쥐여주지 않으면 이 오류가
생길 수 없다. LLM은 표 위에 해설만 붙인다.

### 4.3 화면이 지키는 표시 규율

`scripts/rank_keywords.py:render()`가 정본이고 `sns/web/chat/render.py`가 그대로 이식한다.

| # | 규율 | 깨지면 |
|---|---|---|
| 1 | `rank_std=None` → "미정의"(0.0 아님) | "불일치가 없다"와 "잴 수 없다"가 뒤집힌다 |
| 2 | `filter_mode` 3값(`active`/`passthrough`/`off`)을 각각 다른 문장으로 | 뭉개면 **필터 없는 척**이 된다. 모르는 값도 조용히 접지 않는다 |
| 3 | `unscored`는 별도 후보가 아니다. 단 `top` 컷 **이전** 전량에서 계산되므로 `candidates`와 교집합을 먼저 낸다 | 그냥 세면 "후보 10건 중 23건"이 나온다(실측) |
| 4 | `sources_ok`/`sources_failed` 노출 | 어느 소스가 빠진 결과인지 모른 채 읽는다 |
| 5 | "필터를 꺼 보라" 힌트는 `filter_mode == "active"`일 때만 | 밴드가 자른 게 아닌데 필터 탓으로 오인시킨다 |

> 실 LLM 관통 기록: [docs/spikes/chat-live-run-2026-08-26.md](../spikes/chat-live-run-2026-08-26.md)
> — 최저가 계층(`gpt-5-nano`)에서도 규율 2·4가 지켜짐을 확인했다. 규율 1은 모델이 어길
> 수단 자체가 없다(수치를 넘기지 않는다).

### 4.4 FR-W5와의 경계

챗봇은 **주제 확정까지**다. 확정 시점부터는 FR-W5 시드 발행 경로 그대로다:
`run_cycle(seed_topic=...)` → Content Agent 초안 → 품질·안전 게이트 → needs_review →
승인 화면(§3, :8001) → 발행. 챗봇이 곧바로 세상에 올리지 않는다.

시드 주제는 **저장 전에** FR-Q7 검열을 받는다(`screen_text`). 발행 관문은 *생성된*
콘텐츠만 보므로 그것만으로는 늦다 — 금지 소재 시드가 `topic` 원장에 먼저 적재되고,
막힐 초안에 LLM 비용도 쓴다.
