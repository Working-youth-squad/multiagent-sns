# 10. 웹 대시보드 · 알림 (FR-W)

> 상위: [PLAN.md](../PLAN.md) · 플로우: [diagrams/user-flow.mermaid](../diagrams/user-flow.mermaid)
> **[개정 v2] W3·W4는 필수, W1·W2는 선택** — 근거: 팀 요구사항(발행 성공/실패 알림, "크는/안 크는 이유" 인사이트 탭·그래프는 필수 기능).

## 1. 요구사항

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-W1 | (선택) 채널 온보딩: IG 프로 계정/YouTube 채널 OAuth 연동, 토큰 **암호화 저장**, 검증 핑 | 검증 실패 시 연동 불가 |
| FR-W2 | (선택) 운영 설정: goal·발행 슬롯·주제 도메인·채널/포맷 on-off. 변경=새 국면(이력 보존·기저 재수집) | 변경 시 옛 데이터 불변 |
| FR-W3 | **[필수] 인사이트 탭**: 계정별 추이 차트+성장 기울기(자기 베이스라인 대비) + **auto vs hybrid 비교 4지표**([01](01-실험설계.md) FR-E4) + 알고리즘 신호 스코어보드([09](09-알고리즘-신호-최적화.md) FR-A1) + LLM 분석글(근거/뱃지) | 수치=코드, 분석글=근거 or "근거 부족" |
| FR-W4 | **[필수] 모니터링·알림 = Discord 웹훅**(무료, 구현 최소): 발행 성공/실패·토큰 만료·한도 초과·품질 게이트 차단을 통지. 실패 알림 = **오류 분류**(auth/quota/spam_block/transient/render) + 원문 + **LLM 원인 분석 1줄**(LLM 호출 실패 시 분류명만이라도 발송). 발신 지점 = Publisher 실패 처리부 + 사이클 최상위 catch. 모든 알림은 DB에도 적재(웹 알림 로그와 이중화) | 강제 실패 주입 시 웹훅 수신 + DB 기록 |
| FR-W5 | **[신설 v3] 수동 프롬프트 시드 발행(hybrid 전용)**: 사람이 **주제/프롬프트를 직접 입력**해 사이클을 트리거하는 경로("발행 버튼 + 프롬프트 입력"). 흐름 = 프롬프트 입력 → Content Agent 초안 생성 → 품질·안전 게이트([05](05-콘텐츠생성-품질게이트.md) FR-Q1·Q7) → needs_review 승인 화면(§3) → 발행. 입력 프롬프트도 안전성 검열(FR-Q7) 대상. auto 채널은 스케줄 트리거 유지, 수동 시드는 hybrid에서만 | hybrid에서 사람 입력 프롬프트 → 초안 생성 → 승인 → 발행 관통 |

## 2. 인사이트 탭 구성 (FR-W3 상세)

| 구역 | 내용 | 데이터 출처 |
|---|---|---|
| ① 계정 카드 ×4 | 팔로워·조회 추이, 성장 기울기 | analytics 스냅샷 (코드 집계) |
| ② auto vs hybrid 비교 | 글당 조회·좋아요·참여율·팔로워 증가, 플랫폼별 | FR-E4 |
| ③ 신호 스코어보드 | 공식 신호 기준 상·하위 콘텐츠, 공통 요소(hook_pattern·주제·길이) | FR-A1 |
| ④ 주간 분석글 | "크는/안 크는 이유" — 근거 인용 필수, 소표본 규칙(FR-A4) 적용 | analysis_note |

## 3. hybrid 승인 화면 (FR-E1·FR-Q3의 UI 접점)

- 주제 제안 3~5개 중 선택 → 초안(대본·미리보기) 확인 → 인라인 수정(제목/대본/발행시각) → 승인/반려. 수정 시 `edited_by_human=true` 기록.
- **[신설 v3] 수동 프롬프트 시드 입력(FR-W5)**: 제안 목록 대신 사람이 직접 주제/프롬프트를 입력하는 진입점. 입력 → 초안 생성 후 위와 동일한 승인 흐름으로 합류. 시드 발행분도 `edited_by_human=true`.
