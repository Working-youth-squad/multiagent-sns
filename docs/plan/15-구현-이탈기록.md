# 15. 구현 이탈 기록 (기획서 대비)

> 상위: [PLAN.md](../PLAN.md) · 현재 상태: [13-로드맵-리스크](13-로드맵-리스크.md) §0

## 0. 이 문서의 자리

기획서(01~14)는 **목표 상태**를 적는다. 구현하다 보면 기획서가 정하지 않은 걸 정해야 하고, 때로는 기획서와 다르게 가는 편이 맞다고 판단하게 된다. 그 판단을 여기 남긴다 — **무엇을, 왜 바꿨는가.**

기획서 본문만 고치면 "지금 어떻게 되어 있나"는 남지만 "왜 그렇게 됐나"가 사라진다. 반대로 이 문서만 쓰면 기획서가 낡는다. 둘 다 둔다.

**기록 규칙**

1. 기획서 본문은 목표 상태로 유지한다. 이 문서는 그 위에 얹는 기록이다.
2. 항목은 **추가만** 한다. 판단이 뒤집히면 새 항목으로 뒤집고, 옛 항목은 지우지 말고 남긴다 — 뒤집혔다는 사실이 기록의 일부다.
3. 커밋은 **해시가 아니라 PR 번호와 커밋 제목**으로 가리킨다. 스쿼시 머지되면 개별 해시가 main 히스토리에서 사라진다(실제로 #27이 그렇게 사라져 #31에서 유령 충돌 14건을 만들었다).
4. "왜"를 한 줄로 못 쓰겠으면 그건 아직 판단이 안 선 것이다. 항목을 만들기 전에 판단부터 한다.

### 1.1 영상 3단 레이아웃

**기획서**: [06](06-미디어렌더.md) §4가 "**자체 그래픽**: 코드 화면·직접 그린 도표를 매 영상에 포함"을 NFR-11 안전 요건이자 개발 니치 차별점으로 요구한다. 다만 **어떻게** 넣을지는 정하지 않았다.

**실제**: 화면을 셋으로 나눈다 — 위=주제·부제, 가운데=정사각 940 코드/도표, 아래=자막. `topic`은 영상 내내 고정되는 앵커다.

**왜**: 예전에는 컷마다 제목이 통째로 바뀌어 **중간부터 본 시청자가 "무슨 영상인지"를 잡을 곳이 없었다.** 고정 앵커가 그 자리를 만든다. 위아래 밴드를 검은 바탕으로 두면 글자 대비가 배경 사진에 좌우되지 않는다.

**딸려 나온 정리** — Ken Burns 줌을 걷어내면서 함께 사라진 것들이다:

- 세그먼트 등분 삭제 — 줌이 없으면 같은 컷의 세그먼트는 완전히 동일한 프레임이다.
- ASS 자막(`subtitles.py`) 삭제 — 자막이 컷 단위라 PNG에 직접 그린다.
- 문장 분할 삭제 — **슬라이드 1장 = 컷 1개 = 화면 1장.** 나레이션이 길면 쪼개지 않고 거부한다.

> 마지막 항목은 [06](06-미디어렌더.md) §4의 "시각 페이싱: 2~4초마다 화면 변화"와 긴장 관계다. 3단은 컷을 쪼개지 않는 대신 **한 컷이 길면 거부**하는 쪽을 택했다. 페이싱을 렌더가 아니라 대본이 책임진다.

출처: `feat(render): 영상 3단 레이아웃 — 주제 고정 + 컷별 부제·코드·자막` (#31)

### 1.2 정사각 소스 4단 폴백

**기획서**: 없음. [06](06-미디어렌더.md) §5의 폴백 규칙은 "품질 게이트를 못 넘는 포맷은 **영상 대신 카드뉴스로 강등**"이라 층위가 다르다 — 그건 영상 단위, 이건 컷 단위다.

**실제**: 층이 둘이다.

| 단계 | 시점 | 순서 |
|---|---|---|
| 사진 해소 | **생성 시점 1회**, 렌더 밖 | `image_prompt`(생성) → `image_query`(Pexels) → 못 붙이면 질의만 남김 |
| 렌더 | 렌더 시점 | `코드` → `개념 그림` → `주제 사진`(위에서 해소된 `image_ref`) → `그라데이션` |

**왜 이 순서인가**: 앞의 셋은 우리가 그리거나 못박은 것이라 저작권·네트워크 리스크가 없다. **실사 사진이 마지막인 건 추상 개념을 못 그리기 때문이다** — "list vs set"에 전선 사진이 왔다.

**왜 두 층인가**: **실패가 영상을 죽이면 안 된다.** 스톡이 0건이거나 API가 429를 주는 건 정상 운영에서 늘 있는 일이다. 그 컷만 조용히 그라데이션으로 떨어뜨리고, 사유는 `notes`로 올려 나중에 물어볼 수 있게 남긴다.

**중요**: 사진 해소는 **생성 시점 1회**고 렌더 밖이다. 렌더 시점에 검색하면 같은 `media_spec`이 날마다 다른 영상을 낳아 FR-M1(같은 spec → 같은 checksum)이 깨진다.

출처: `feat(images): 컷별 주제 사진 트랙 — Pexels 검색 → FR-Q7 게이트 → 정사각 고정`, `feat(cycle): 사진 해소를 사이클에 배선 + Pexels 크레딧 줄` (#31)

### 1.3 개념 그림 6종

**기획서**: [06](06-미디어렌더.md) §4의 "직접 그린 도표". 종류는 미지정.

**실제**: `emphasis` · `compare` · `remember` · `flow` · `steps` · `terminal`.

**왜**: 개발 콘텐츠에서 반복적으로 필요한 그림꼴이 이 여섯이다. 자유형 도표를 LLM에 맡기면 결정론이 깨지고 품질 편차가 커진다. 꼴을 고정하고 내용만 채우게 하면 같은 입력이 같은 그림을 낳는다(FR-M1).

출처: `feat(render): 개념 그림 3종 — 정사각을 우리가 그린다`, `feat(render): 개념 그림 3종 추가 — flow · steps · terminal` (#31)

### 1.4 생성 이미지는 기본 미배선

**기획서**: 없음. [01](01-실험설계.md) §2가 생성형 **영상** 툴을 스코프 아웃했을 뿐, 생성 **이미지**는 다루지 않았다.

**실제**: `sns.render.images.generate` 모듈은 만들어 두되 **기본 배선에서 뺐다.** Content Agent 프롬프트에서 `image_prompt`를 제거했고, 켜려면 명시로 주입해야 한다. 추가로 **코드가 한 컷이라도 있는 영상에서는 생성 이미지를 아예 거부**한다(영상 단위 규칙).

**왜 — A/B 실측**: 같은 영상(ORM N+1)에서 컷 1·5만 `gpt-image-1`로 바꿔 나란히 놓고 골랐다. 화풍은 잘 맞았지만, **개발 콘텐츠의 핵심 컷은 대개 숫자와 비교**였다. "101번 → 2번"을 개념 그림은 글자로 쓰지만 생성 이미지는 화살표 개수를 세게 만든다. 생성이 이기는 자리는 훅처럼 인상이 전부인 컷 하나뿐이었고, **그 한 컷 때문에 과금·비결정론을 상시 배선할 이유가 없다.**

모듈을 지우지 않은 이유: 화풍 비교(`scripts/preview_generated_image.py`)와, 판단이 바뀔 때의 진입점이다. 기본값을 `generate_image`로 두면 결제가 켜진 계정에서 사이클이 조용히 돈을 쓴다.

출처: `feat(images): 생성 이미지 트랙 — 만들어두되 기본 배선에서 뺀다`, `docs(images): 생성 이미지 대신 개념 그림 — A/B 결과와 근거를 코드에 남긴다`, `feat(spec): 생성 이미지는 코드 없는 영상에서만 — 영상 단위 규칙` (#31)

### 1.5 근접중복 관문 + `blocked` 결과

**기획서**: [05](05-콘텐츠생성-품질게이트.md)에 근접중복 항목이 없다.

**실제**: `media_spec` 하나로 지문을 떠서 최근 발행분과 비교한다(`sns.quality.signature`). 걸리면 **렌더하지 않고** 원고만 `needs_review`로 남기고, 사이클 결과에 `blocked`를 돌려준다.

**왜**: `check_card`에 유사도 검사가 있었지만 **한 번도 동작한 적이 없었다.** 유일한 호출부가 `recent_signatures`를 안 넘겨 기본값 빈 튜플로 항상 통과했고, 영상 게이트에는 검사 자체가 없었다. 어제와 거의 같은 Cursor 영상이 두 번 나간 이유의 절반이다.

세 가지 설계 판단이 딸려 있다:

- **포맷별이 아니라 `media_spec` 하나로 본다.** 카드용·영상용을 따로 만들면 한쪽만 배선되는 같은 사고가 다시 난다.
- **지문에서 코드는 뺐다.** 판단 대상은 "무엇을 말했나"이지 "어떤 스니펫을 띄웠나"가 아니다. 코드를 넣으면 같은 대본에 스니펫만 바꾼 재탕이 통과한다.
- **관문을 렌더 앞으로 옮겼다** (안전 검열도 함께). 막힐 콘텐츠에 TTS·이미지 생성 비용을 쓸 이유가 없다. 이미지 해소는 텍스트를 바꾸지 않으므로 그 전에 봐도 판정이 같다.

`blocked`는 `failed`(도메인 오류)와 구분한다 — **원고는 멀쩡히 있고 판단만 남은 상태**다.

실 데이터 확인: 발행분끼리 유사도가 자기 자신 1.00(차단), 다른 주제 0.02(통과).

출처: `feat(quality): 근접중복 관문을 포맷 무관하게 — 그리고 렌더 앞으로` (#31)

### 1.6 LLM 텍스트 모델을 env로

**기획서**: [03](03-멀티에이전트.md)은 LLM 혼합 전략을 다루지만 모델 교체 경로는 없다.

**실제**: `GEMINI_MODEL` 환경변수로 고른다. 비우면 기본값.

**왜**: 무료 티어 쿼터가 **모델별로 따로** 걸린다(`GenerateRequestsPerDayPerProjectPerModel-FreeTier`, 하루 20건). flash가 소진돼도 flash-lite는 남아 있다. **코드를 고쳐야만 모델을 바꿀 수 있으면 쿼터가 떨어진 그 순간 그날 작업이 멈춘다.**

출처: `feat(agents): 텍스트 모델을 env로 — 무료 티어 쿼터가 모델별이다` (#31)

### 1.7 classic 렌더러 병존

**기획서**: 없음.

**실제**: 3단이 대체한 옛 렌더러(그라데이션+타이포, 문장 단위 컷, Ken Burns)를 `sns/render/video/classic/`에 보존한다. **자동 사이클에 배선하지 않는다** — 진입점은 `scripts/render_classic.py`뿐이다. 원본은 태그 `renderer/classic-v1`.

**왜**: 지웠다가는 비교도 되돌림도 못 한다. 다만 사이클에 배선하면 spec 판별 유니온·프롬프트 분기·테스트 2벌이 따라오므로, **보존과 배선을 분리**했다. 나중에 배선하고 싶어지면 배선만 얹으면 되고 보존된 코드는 다시 안 건드린다.

> 주의: classic으로 뽑은 영상은 [06](06-미디어렌더.md) §4의 "매 영상에 코드·도표" 요건을 **구조적으로 못 채운다**. 그래서 사이클 기본값이 아니다.

출처: `feat(render): classic 영상 템플릿 보존 — 3단이 대체한 옛 모양을 되살린다` (#33)

### 1.8 주제 도메인을 팩으로 분리

**기획서**: 없음. [PLAN.md](../PLAN.md) §1 한 줄 정의가 **"개발자 주제 콘텐츠"**로 시작하고, [01](01-실험설계.md) `FR-E2`가 "동일 주제 도메인"을 통제 변수로 못박는다. 즉 기획서는 도메인이 **하나로 고정**된다는 전제 위에 있고, 그것을 갈아끼우는 이야기는 어디에도 없다.

**실제**: `sns/domain/` 패키지가 도메인별로 갈리는 값을 전부 갖는다.

```
ref · audience · topic_domain · categories
grounding_prompt · trend_sources · search_terms
concept_kinds · concept_examples
square_sources · square_guidance
```

주입은 기본값 있는 키워드 인자다(`NFR-2` 주입식 규율). 기본값이 `DEVELOPER`라 **기존 호출부와 테스트가 한 줄도 바뀌지 않았다.**

**왜**: 파이프라인의 88.5%(7,361/8,322줄)는 도메인 중립인데, "무엇을 다루는 채널인가"만 여러 자리에 흩어져 박혀 있었다. 어디에 있는지가 코드를 읽어야만 보였고, 그래서 **하나를 빠뜨렸다**:

```python
naver_search.query     = "개발자"
naver_datalab.keywords = ("개발자", "파이썬", "AI")
```

소스 **목록**은 팩으로 뺐는데 그 소스가 **무엇을 검색하는지**는 하드코딩이었다. 도메인을 바꿔도 네이버는 계속 "개발자"를 검색한다 — 문구가 아니라 동작이라, 도메인 전환 여부와 무관한 결함이었다. 흩어져 있으면 이런 걸 못 찾는다는 게 분리의 진짜 이유다.

**경계**: 구조는 모듈에, 값은 팩에. 개념 그림의 필드·검증·렌더는 [sns.render.concept_image]에 남고 팩은 *어떤 종류를 쓸지와 예시 문구*만 갖는다. `compare`처럼 중립인 그림꼴도 예시는 도메인 향이 강해서(`"list vs set"`, `"O(n) -> O(1)"`) 함께 갈아야 하기 때문이다.

**정사각 소스가 마지막 뿌리였다.** 렌더러의 분기가 `code → concept → image → gradient`로 박혀 있었고 첫 줄이 코드다. 팩이 `square_sources`를 정하고, 파서가 목록에 없는 소스의 슬라이드 필드를 **거부**한다. 프롬프트에서 안내를 빼는 것만으로는 1차 방어선뿐이다 — 에이전트가 안내를 무시하거나 옛 spec을 재사용하면 코드를 안 쓰는 도메인의 영상에 파이썬 코드가 렌더된다.

순서는 `VideoSpec`에 실어 보낸다. 렌더러가 팩을 직접 알지 않게 — 파서가 이미 팩을 알고, 렌더러의 일은 "이 spec을 그려라"다. `같은 media_spec + 같은 팩 → 같은 VideoSpec → 같은 mp4`로 `FR-M1` 결정론도 유지된다.

**손실**: `TopicCategory` Literal이 `str`로 완화됐다. 카테고리가 팩에서 오면 Literal을 못 쓴다. 실질 방어선은 그대로 — `choose_topic`이 런타임에 팩 목록으로 검증한다.

**남긴 것**: docstring·주석의 도메인 사례는 지우지 않았다. `"list vs set에 전선 사진이 왔다"`, `"코드 영상에서는 개념 그림이 이겼다"` 같은 건 **왜 그렇게 됐는지의 기록**이고 실제 실측이다. 도메인이 바뀌어도 그때 그 판단을 했다는 사실은 유효하다.

> 이 항목은 §3.2의 `topic_category` 미저장과 겹친다 — 카테고리가 팩에서 오는데 **DB에는 저장되지 않아** 카테고리별 성과 분석은 여전히 불가능하다.

출처: `refactor(domain): 주제 도메인을 팩으로 분리`, `트렌드 질의어와 정사각 안내도 팩으로`, `정사각 소스를 팩으로` (#34)

## 3. 의도적 미완 — 기획서대로 가려는데 아직 절반

### 3.1 FR-Q7 안전 검열 = 룰 절반만

**기획서**: [05](05-콘텐츠생성-품질게이트.md) FR-Q7은 "**룰(금지어·패턴) + LLM 판정 이중 검사**"를 요구한다.

**실제**: **결정론(룰) 절반만 배선**됐다. LLM 판정 쪽은 미배선이다. `sns/quality/safety.py` 모듈 docstring이 이 사실을 명시하고 있다.

**왜 절반이 먼저인가**: 룰은 결정론이라 같은 입력이 같은 판정을 낸다 — FR-Q7이 요구하는 성질이다. LLM 쪽은 비결정론이라 별도 조각으로 다룬다.

**룰이 못 잡는 것** (남은 절반의 몫):

- **사실 오류** — "Prettier가 타입 오류를 잡아준다"에는 금지어가 하나도 없다.
- **맥락 의존 판단** — 같은 단어가 비방일 수도, 인용일 수도 있다.

**의도적으로 안 막는 것** (룰의 몫이 아니라고 판단):

| 유형 | 예 | 판단 |
|---|---|---|
| 과장 | "확 빨라집니다", "이거 모르면 손해" | 막지 않는다 — 후크의 핵심이다 |
| 근거 없는 수치 | "생산성 300%" | 여기서 막지 않는다 — Content Agent 프롬프트의 몫 |
| 금지 소재 | 음란·정치·비방·불법 복제 | **막는다** |

수치를 정규식으로 막으면 정당한 수치("메모리 40% 감소")까지 죽는다. 오탐 비용이 커서 룰로 다룰 자리가 아니다.

출처: `feat(quality): FR-Q7 텍스트 안전 검열 — 결정론 절반을 배선` (#31)

### 3.2 주제 카테고리가 DB에 저장되지 않는다

**기획서**: [04](04-트렌드조사.md) §4가 *"선정된 카테고리는 `content_item.topic_category`([11](11-데이터모델.md))에 **기록되어 성과 분석·향후 밴딧 arm 축**([08](08-지표-학습.md) `FR-L3`)이 된다"* 고 한다.

**실제**: **그 컬럼이 없다.**

```
sns/db/migrations/*.sql 에서 topic_category  →  0건
```

카테고리는 코드가 런타임에 검증만 하고(`choose_topic`), `TopicResult.category`로 들고 다니다 버려진다. 러너가 `save_content_item`에 넘기지 않는다.

**무엇이 막히나**: **카테고리별 성과 분석이 불가능하다.** "꿀팁이 신기술보다 잘 되는가"를 물을 수 없고, `FR-L3` 밴딧의 arm 축 하나가 통째로 없다. 카테고리 5종을 정한 [04](04-트렌드조사.md) §4의 목적 절반이 여기서 끊긴다.

**왜 지금 안 고쳤나**: 마이그레이션 + 러너 배선 + 집계 쿼리가 함께 가야 하는데, 그 앞에 [13](13-로드맵-리스크.md) §0의 지표 적재가 통째로 비어 있다. **저장할 성과 자체가 아직 없어서** 컬럼만 먼저 만들면 빈 칸이 쌓인다. 지표 적재와 같은 작업으로 묶는 게 맞다.

> §1.8에서 카테고리를 팩으로 뺐지만 이 갭은 그대로다 — 팩이 카테고리를 **정하는** 것과 DB가 그것을 **기록하는** 것은 다른 문제다.
