# 09. 알고리즘 신호 최적화 (서비스 기능)

> 담당 역할: **역할 B (콘텐츠·에이전트)** · 관련 요구사항: 4, 5, 12, 13 · 상위 문서: [기획서 총괄](../기획서.md)
> 근거: 3갈래 딥리서치 (2026-08) — ① 인스타 공식 랭킹 신호 ② 유튜브 쇼츠 공식 랭킹 신호 ③ 추천시스템 기술 구조·제3자 실증 연구

## 1. 설계 원칙 — 규칙이 아니라 신호를 최적화한다

조사의 핵심 결론 3가지가 이 기능의 설계 원칙이다:

1. **알고리즘 "규칙" 역공학은 유효기간이 짧다** (감사 재현성 연구, arXiv 2504.18140 — 감사 결과가 재현되지 않고 빠르게 낡음). 안정적인 것은 **목적함수의 방향**뿐: 두 플랫폼 모두 "시청시간·완주·공유·만족도 확률의 가중합"을 최적화한다 (Meta Value Model, YouTube 기대 시청시간 예측 — 공식 엔지니어링 문서·논문 확인).
2. **신규 콘텐츠는 시드 오디언스 테스트로 운명이 결정된다** — 소규모 노출 → 초기 반응 → 단계 확산. 인스타(Mosseri "오디션" 비유 + Trial Reels 기능으로 공식화), 유튜브(Todd Sherman 공식 설명, 구독자 수 무관) 모두 공식 확인. 틱톡류는 실시간 학습(Monolith)이라 게시 후 수 시간의 신호가 결정적.
3. **결과 분산은 구조적이다** — 같은 품질도 조회수가 10배 이상 벌어진다 (Salganik Music Lab: 사회적 증폭은 불평등·예측불가능성을 키움 / "Shorter Is Different": 숏폼은 팔로워-조회수 결합이 약해 계정 내 분산이 큼). 따라서 **개별 영상 1건의 성패로 원인을 단정하는 것은 대부분 소음** — 소표본 통계 정직성이 기능 신뢰도의 핵심.

→ 서비스는 규칙을 하드코딩하지 않고, **공식 신호를 API로 측정 → 자기 계정 기준선 대비 비교 → 지속 재추정**하는 구조로 만든다.

## 2. 공식 확인된 랭킹 신호 (통설과 구분)

### 인스타그램 릴스 (출처: Instagram Ranking Explained + Mosseri 2024~25 발언)

| 신호 | 설명 | API 측정 |
|---|---|---|
| **watch time** | 시청 시간·완주 확률 | `ig_reels_avg_watch_time`(ms) ÷ 영상 길이 = 완주 근사 |
| **likes per reach** | 도달 대비 좋아요 (팔로워 랭킹에서 비중↑) | `likes` ÷ `reach` |
| **sends per reach** | 도달 대비 DM 전송 (비팔로워 추천에서 비중↑) | `shares` ÷ `reach` |
| 저장 | 품질 신호 | `saved` ÷ `reach` |
| 훅 통과 | 첫 3초 스킵 비율 | `reels_skip_rate` (도입 중 메트릭 — 가용 시) |
| **감점 요인 (공식)** | 타 플랫폼 워터마크, 저해상도, 음소거, 텍스트 과다, 중복 게시, 어그리게이터(30일 내 무편집 재게시 10회↑) | 발행 전 코드 검사 가능 (§3 F2) |

### 유튜브 쇼츠 (출처: 공식 헬프센터 + Creator Insider — Todd Sherman/Beaupré)

| 신호 | 설명 | API 측정 |
|---|---|---|
| **viewed vs swiped away** | 피드 노출 시 시청 선택률 — 1차 지표 | `engagedViews` ÷ `views` (가장 좋은 API 근사. 2025-03부터 views=재생 시작, engagedViews=의미 있는 시청) |
| **평균 시청 시간·비율** | 헬프센터 명시 | `averageViewDuration`, `averageViewPercentage` |
| 만족도 | 좋아요 + 시청 후 설문 | 설문은 API 미제공 |
| 구독 전환 | 쇼츠→구독 통로 | `subscribersGained` (video별) |
| 공식 부인된 통설 | 특정 길이 보너스 없음, 발행 시간 대체로 무관, 구독자 수는 랭킹 요인 아님 | — |
| 정책 경계 | "비진정성 콘텐츠"(템플릿 양산) = 수익화 배제 | [04-영상제작](04-영상제작.md) §5와 동일 대응 |

**통설(비공식)로 분류된 것** — 서비스 문구에서 "공식"이라 쓰지 않는다: sends 가중치 배수, 확산 시간표(첫 1시간 등), 최적 길이 30~90초, 해시태그·발행 요일의 직접 랭킹 반영. 발행 시간 최적화는 근거가 약하므로 부가 옵션으로만 둔다(현 설계의 슬롯·지터는 스팸 방지 목적이지 랭킹 최적화 주장이 아님).

## 3. 서비스 기능 5종

| # | 기능 | 내용 | 구현 위치 | 근거 강도 |
|---|---|---|---|---|
| **F1** | **알고리즘 신호 스코어보드** | 게시물별로 공식 신호를 계산(IG: shares/reach·likes/reach·saved/reach·완주 근사, YT: engagedViews/views·averageViewPercentage) → **계정 자체 기준선(중앙값) 대비** 상·하위 태깅 → 상위 콘텐츠의 공통 요소(훅 패턴·주제·길이)를 인사이트 탭에 리포트 | analytics-sync 확장 + [07-웹화면](07-웹화면.md) 인사이트 탭 ④구역 | 상 (공식 신호 1:1) |
| **F2** | **발행 전 감점 요인 검사기** | 렌더 산출물에서 해상도(<1080×1920), 음소거, 자막 안전영역 위반, 직전 N건과 스크립트/구성 유사도(중복·양산 판정 방어)를 코드로 검사 → 미통과 시 발행 차단. 인스타 공식 감점 목록·유튜브 비진정성 정책과 1:1 대응 | [04-영상제작](04-영상제작.md) §1 규격 검증 게이트에 통합 | **최상** (공식 감점 목록) |
| **F3** | **초기 확산 조기 판정** | 시드 테스트 구조에 근거해 게시 후 6·24·72시간 지표 스냅샷을 폴링 → 계정별 "첫 N시간 → 최종 성과" 상관이 쌓이면 확산/소멸 조기 분류 → 소멸 판정 시 Discord 알림 + 훅·도입부 개선 제안 | analytics-sync 폴링 주기 확장(발행 직후 다회) + [05-발행·계정안전](05-발행-계정안전.md) §5 알림 | 중~상 (구조는 공식, 판정선은 자기 데이터) |
| **F4** | **소표본 정직 통계** | 성과 분석 시 log(조회수)·계정 내 백분위만 사용(heavy-tail 방어), 게시물 30건 미만이면 회귀 금지 — 스피어만 상관+신뢰구간만 표시하고 "아직 결론 불가" 명시, UI에 "동일 품질도 조회수 10배 차이 가능" 기본 안내 | [06-지표·인사이트](06-지표-인사이트.md) §3 분석글 규칙에 추가 | 상 (Music Lab·분산 연구) |
| **F5** | **알고리즘 변화 감지** | 계정별 도달/조회 시계열에 체인지포인트 탐지(CUSUM) 적용. **핵심 차별점: 우리는 계정 4개를 보유하므로, 다수 계정에서 동시에 변화점이 잡히면 "내 콘텐츠 문제"가 아니라 "알고리즘 변화"로 판정** → 인사이트 분석글에 반영(잘못된 귀인 방지) | analytics-sync 후처리 + insight_reports | 중 (방법론 검증됨, 표본 축적 필요) |

## 4. 기존 설계에의 반영

- **수집 지표 확장** ([06-지표·인사이트](06-지표-인사이트.md) §1): `post_insights`에 컬럼 추가 — IG: `reach`, `shares`, `saved`, `avg_watch_time_ms`, `skip_rate`(가용 시) / YT: `views`, `engaged_views`, `avg_view_duration_s`, `avg_view_percentage`, `subscribers_gained`. 발행 직후 6·24·72h 다회 폴링(F3용)으로 `post_insights`를 게시물×시점 구조로 사용
- **reward 산식 정렬** ([06](06-지표-인사이트.md) §2): 원시 조회수가 아니라 **플랫폼 목적함수와 같은 방향의 신호**(완주 근사·공유율·engagedViews 비율)를 가중합. 조회수는 heavy-tail이라 log 변환 후 사용
- **에이전트 학습 입력** ([03-딥에이전트](03-딥에이전트-트렌드조사.md) §2): 플레이북 갱신의 근거 데이터를 F1 스코어보드 출력으로 통일 — "조회수가 높았다"가 아니라 "완주율·공유율이 계정 기준선보다 높았다"를 교훈의 근거로
- **일정** ([08-일정·역할분담](08-일정-역할분담.md)): F2는 2주차(렌더 게이트에 포함), F1·F3은 3주차(analytics-sync·인사이트 탭과 함께), F4는 분석글 규칙으로 즉시, F5는 데이터 축적 후(3주차 말 시범)
