# 05. 콘텐츠 생성 · 품질 게이트

> 상위: [PLAN.md](../PLAN.md) · 관련: [04-트렌드조사](04-트렌드조사.md), [06-미디어렌더](06-미디어렌더.md)

## 1. 콘텐츠 생성 (FR-G)

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-G1 | Topic Agent가 개발자 주제 도메인에서 주제 발굴, `topic` 풀 + `topic_stats` 참조 (+외부 트렌드 FR-G4, [04](04-트렌드조사.md)). **[신설 v3] 카테고리 5종(신기술/기초지식/꿀팁/현직자 일상/개발자 유머) 중 택1 + 선정 원칙(설명 난이도 하한·호기심 후크) 적용([04](04-트렌드조사.md) §4)** | 주제가 `content_item.topic_id`로 추적, **발행 콘텐츠 전수가 `content_item.topic_category` 보유** |
| FR-G2 | Content Agent가 주제 → 포맷별 산출물 생성: 피드=카드뉴스 문안, 릴스/쇼츠=영상 대본(장면·자막·나레이션) | format별 스키마 준수한 `media_spec` 생성 |
| FR-G3 | 콘텐츠는 발행 전 **결정론 렌더 스펙(`media_spec`)** 으로 확정 저장(LLM 재호출 없이 재현 가능) | 같은 content_item→같은 렌더 입력 |
| FR-G5 | **[신설 v2]** Content Agent는 **훅 문장을 본문과 분리 생성**하고 패턴 5종(bold_claim/curiosity/story/shock/question)을 `content_item.hook_pattern`에 기록 — §2 체크리스트 "훅" 항목의 측정 가능화 + 성과 분석 축 + 향후 밴딧 arm([08](08-지표-학습.md) FR-L3) | 발행 콘텐츠 전수가 hook_pattern 보유 |

## 2. 콘텐츠 품질 게이트 (FR-Q) — 발행 전 하한 검증

> 근거: 템플릿 합성 콘텐츠의 시장 하한 미달이 프로젝트 성패에 직결. 품질을 "학습으로 나중에 개선"에만 맡기지 않고 **발행 전 게이트**로 하한을 강제한다.

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-Q1 | **발행 전 자동 품질 검사**: 렌더된 `media_asset`이 게시되기 전 규격·가독성 하한 통과(영상 9:16·길이 범위·오디오 존재/무음 아님, 카드 텍스트 오버플로우/최소 대비/필수 필드) + **[확장 v2] 알고리즘 감점 요인 검사(FR-A2, [09](09-알고리즘-신호-최적화.md))**. 미통과=발행 차단 | 규격 위반 자산이 `publish_attempt`에 진입 못 함 |
| FR-Q2 | 검사 결과를 `media_asset`에 기록(`quality_status`: passed/failed/needs_review, `quality_report`). 실패는 사유 원문 보존 | 실패 자산의 사유 조회 가능 |
| FR-Q3 | **사람 검수 훅**: `needs_review` 상태로 운영자 승인 후 발행하는 수동 관문. **[개정 v2] hybrid 채널의 상시 관문으로 사용**(채널 단위 mode, [01](01-실험설계.md) FR-E1). auto 채널은 Phase 0~1 초기에만 옵션 | 미승인 자산 발행 안 됨 |
| FR-Q4 | 품질 기준(임계값)은 **코드 상수/설정으로 외부화**(프롬프트 아님) — 결정론 재검사 가능 | 같은 자산·같은 기준→같은 판정 |
| FR-Q5 | **정성 품질 하한(사람 정의)**: Phase 0 품질 스파이크에서 "발행 가능" 정성 기준을 체크리스트로 사전 확정(§3), 버전드 문서 보관 | Phase 1 발행 자산 전수가 항목별 pass/fail 기록 보유 |
| FR-Q6 | **Phase 0 정성 게이트의 정량 문턱**: 품질 스파이크는 **[개정 v2] 포맷별 5~8건**(2~3주 일정 압축 — 원안 20건)을 **리뷰어 2인 이상**이 독립 판정(갈리면 fail), 전항목-pass 비율 **≥ 60%**(초안)면 통과. 미달 시 FR-Q 게이트를 Phase 1 필수로 승격 + 템플릿/대본 개선을 학습 루프보다 선행 | 스파이크 리포트에 표본수·통과율·리뷰어 수 기록 |
| FR-Q7 | **[신설 v3] 발행 전 안전성 검열(금지 소재 필터)**: 콘텐츠 생성 직후·렌더 전에 **금지 소재를 차단** — 정치 편향·특정인 비방/저격·저작권 침해(타인 코드/이미지 무단)·NSFW·검증 안 된 허위 주장. **룰(금지어·패턴) + LLM 판정 이중 검사**, 미통과 = 발행 차단·`needs_review`. 금지어/카테고리는 **코드 상수/설정으로 외부화**(프롬프트 아님, 결정론 재검사) | 금지 소재 주입 시 발행 차단 + 사유 기록, 같은 입력→같은 판정 |

## 3. 발행 가능 정성 체크리스트 (Phase 0 확정 · v1 초안)

FR-Q1~Q4는 규격 하한(형식)만 잡는다 — 시장 하한을 좌우하는 *실질* 품질(볼 이유가 있는가)은 아래를 사람이 판정한다. 항목·문턱은 Phase 0 스파이크에서 확정해 버전으로 고정.

| 축 | 통과 기준(초안) | 판정 |
|---|---|---|
| **훅(첫 2초/첫 화면)** | 스크롤을 멈출 이유가 첫 프레임/카드 1장에 있는가 — **[v2] hook_pattern 5종 중 하나가 명시적으로 적용됐는가** | pass/fail |
| **정보 밀도** | 개발자에게 "새로 알게 된 것" 1개 이상(자명한 재탕 아님) | pass/fail |
| **가독 리듬** | 자막/나레이션 속도를 따라갈 수 있는가, 한 장면 과밀 아님 | pass/fail |
| **완성감** | 자동합성 티(어색한 TTS 끊김·빈 여백·깨진 정렬)가 "발행 못 할 수준"은 아님 | pass/fail |
| **CTA/마무리** | 끝맺음이 있는가(다음 행동·요약) | pass/fail |

> 전 항목 pass = 발행 가능. 1개라도 fail = `needs_review`(사람 승인 전 발행 차단). 통과율이 낮으면 → 템플릿/대본 프롬프트 개선이 학습 루프보다 선행 과제다.
