# 04. 트렌드 조사 (무료 외부 소스)

> 상위: [PLAN.md](../PLAN.md) · **[신설 v2]** — Topic Agent의 입력이 내부 `topic_stats`뿐이면 콜드 스타트 시 주제 발굴 경로가 없다.

## 1. 요구사항 (FR-G4)

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-G4 | Topic Agent는 `research_trends` 툴로 **무료 외부 트렌드 소스**를 조회해 주제 발굴에 사용. 소스 일부 실패 시 조용히 제외하고 계속. **리서치로 확인 안 된 내용은 소재로 쓰지 않음**(프롬프트 규칙, 할루시네이션 방지) | 콜드 스타트 사이클에서 외부 소스 기반 topic 생성, 소스 1개 강제 실패 시에도 사이클 완주 |

## 2. 소스 구성 (전부 무료)

| # | 소스 | 방식 | 비용/한도 |
|---|---|---|---|
| 1 | Google Trends 한국 급상승 | RSS 파싱 | 무료, 무인증 |
| 2 | 네이버 검색 API (블로그/뉴스) | 공식 API | 무료 25,000회/일 |
| 3 | 네이버 데이터랩 | 검색량 30일 추이 → 상승/유지/하락 판정 | 무료 1,000회/일 |
| 4 | YouTube 인기영상 | `chart=mostPopular&regionCode=KR` | 1unit/회 (일 10,000) |
| 5 | GitHub 트렌딩 / GeekNews RSS | 개발 니치 특화 | 무료 |
| 6 | LLM 웹 그라운딩 (선택) | Gemini `google_search` | 무료 티어 내 |

**구현 원칙**: 소스별 타임아웃(10초) + 실패 시 null 반환 후 계속 — 하나 죽어도 리서치는 계속된다. 결과는 마크다운 다이제스트로 합쳐 Topic Agent 프롬프트에 주입.

## 3. 산출

- 다이제스트 → Topic Agent가 `topic_stats`(과거 성과)·`playbook`(학습된 지침)과 겹쳐 주제 선정.
- hybrid 채널([01](01-실험설계.md) FR-E1)은 주제 3~5개를 제안 상태로 저장 → 사람 선택 대기.

## 4. 주제 카테고리 · 선정 원칙 [신설 v3]

> 배경: 기존 FR-G1은 "개발자 주제 도메인"이라고만 두어 *어떤 주제를 왜 고르는가*가 프롬프트에 위임돼 있었다. 콜드 스타트 초기 편차를 줄이고 "설명이 쉽고 사람이 호기심을 갖는 콘텐츠"라는 팀 편집 방향을 명시하기 위해 **카테고리 5종 + 선정 원칙**을 고정한다. (thin spec 유지 — 카테고리·원칙만 스펙, 실제 문안은 프롬프트/플레이북에 위임.)

### 4.1 주제 카테고리 (5종)

| 카테고리 | 정의 | 호크 예시 | 설명 난이도 |
|---|---|---|---|
| **신기술** | 최근 뜬 도구·릴리스·트렌드 | "이거 나온 지 일주일인데 벌써 다들 쓴다" | 중 |
| **기초지식** | 자주 헷갈리는 CS·언어 개념 | "아직도 이거 헷갈리면 3초 컷 정리" | 하 |
| **꿀팁** | 바로 쓰는 생산성·단축키·도구 | "이 단축키 모르면 하루 10분씩 손해" | 하 |
| **현직자 일상** | 실무 현장·개발 문화·에피소드 | "회사에서 이런 코드 보면 벌어지는 일" | 하 |
| **개발자 유머** | 공감 밈·상황극 | "우리 회사 레거시, 실화 기반" | 하 |

### 4.2 선정 원칙 (Topic Agent 프롬프트 규칙으로 고정)

1. **설명 난이도 하한** — 한 컷/한 카드로 이해되는 주제만 채택. 사전 배경지식이 3개 이상 필요하면 탈락(또는 더 쉬운 하위 주제로 분해).
2. **호기심 후크 필수** — 첫 프레임/첫 카드에서 "왜?·헐·나도"를 유발할 수 있어야 한다. 훅 패턴 5종([05](05-콘텐츠생성-품질게이트.md) FR-G5)과 연결.
3. **리서치 그라운딩** — FR-G4 외부 트렌드로 확인되지 않은 사실은 소재로 쓰지 않는다(할루시네이션 방지, §1 규칙 유지).
4. **카테고리 배분** — auto 채널은 성과(`topic_stats`) 기반으로 카테고리를 스스로 배분, hybrid 채널은 사람이 배분·조정 가능([01](01-실험설계.md) FR-E1).

> 선정된 카테고리는 `content_item.topic_category`([11](11-데이터모델.md))에 기록되어 성과 분석·향후 밴딧 arm 축([08](08-지표-학습.md) FR-L3)이 된다.

## 5. 질의어 기반 키워드 랭킹 [신설 v5]

§2의 소스들은 **고정 피드**라 "오늘 뭐가 뜨나"는 답하지만 "사용자가 넣은 키워드 주변에
뭐가 뜨나"는 답하지 못한다. 챗봇이 키워드를 받는 경로를 위해 **질의어를 받는 소스 3종**과
그 결과를 종합하는 통계를 더한다.

### 5.1 소스 3종 (전부 무인증)

| 소스 | 엔드포인트 | 주는 것 |
|---|---|---|
| `naver_autocomplete` | `ac.search.naver.com/nx/ac` | 네이버 검색창 연관어(인기순) |
| `google_suggest` | `suggestqueries.google.com/complete/search` | 구글 검색창 연관어 |
| `youtube_suggest` | 〃 `ds=yt` | 유튜브 검색창 연관어 |

**검색어**(소비자가 친 글)라는 점이 뉴스·영상 **제목**(언론·크리에이터가 쓴 글)과 다르다.
API 키가 필요 없어 `NAVER_CLIENT_ID` 등과 무관하게 항상 동작한다.

> 요청에 **User-Agent를 반드시 단다.** 없으면 구글 자동완성이 EUC-KR로 응답해
> `json.loads`가 죽는다(실측 2026-08-25). `oe=utf-8`도 함께 보내 UA 스니핑에 기대지 않는다.

### 5.2 통계 — 소스 원값을 섞지 않는다

소스마다 리스트 길이가 달라 등수를 그대로 비교할 수 없고, 데이터랩 ratio·조회수 같은
원값은 단위가 달라 합치면 단위 차이만 측정한다. 그래서 **백분위 등수**(`등수 ÷ (길이+1)`)로
바꾼 뒤 후보별로 세 값을 낸다.

| 값 | 뜻 | 쓰임 |
|---|---|---|
| `present_count` | 몇 개 소스가 이 키워드를 내놨나 | 정렬 1순위 (교차검증 강도) |
| `observed_mean` | **관측된 소스에서만** 낸 평균 등수 | 정렬 2순위 (인기, 낮을수록 위) |
| `rank_std` | **관측된 소스들 사이의** 등수 불일치 | 밴드 필터. `None` = 관측 1건이라 정의 불가 |

**결측은 대입값이지 관측값이 아니다.** 어떤 소스 목록에 없으면 그 소스의 등수는 1.0으로
채우지만, 그 값은 **분산에 넣지 않는다**. 넣으면 분산이 "불일치"가 아니라 "결측이 몇 개인가"를
재게 되어, 두 소스가 아는 키워드와 한 소스만 아는 밈이 같은 표준편차를 받는다(실측 확인).
정렬도 같은 이유로 대입값이 섞인 평균에 맡기지 않는다 — 1.0이라는 상수가 "몇 소스가
봤나"와 "얼마나 높았나"의 교환비를 혼자 정하게 되는데, 그 값에 근거가 없다.

### 5.3 밴드 필터와 세 가지 모드

후보 풀의 `rank_std` 분포에서 25~75 퍼센타일 밖을 자른다(절대 임계값이 아니라 상대 위치).
경계는 **rank_std가 정의된 후보들만으로** 계산하고, 관측 1건인 후보는 판정하지 않고
통과시키되 `unscored`로 따로 센다.

| `filter_mode` | 뜻 |
|---|---|
| `active` | 밴드를 실제로 적용했다. `band`에 경계가 있다 |
| `passthrough` | 켰지만 표본 부족 — 참여 소스 < 2 또는 정의된 후보 < 4 |
| `off` | 호출자가 껐다 |

셋을 뭉뚱그려 "걸렀다"고 말하면 **필터 없는 척**이 된다. 자동완성 소스가 서로 잘 겹치지
않는 질의어("개발자")에서는 정의된 후보가 2개뿐이라 `passthrough`가 나오고, 모듈이 그
사실을 `reason`에 그대로 적는다.

### 5.4 관련성은 판정하지 않는다

이 통계는 등수 분산만 본다 — 밈·오타도 통과한다. 무엇이 부적절한지는 도메인이 정하는
문제라, 질의어에서 부정 프롬프트를 파생시키는 쪽이 `exclude=` 인자로 목록을 주입한다.
기본값은 비어 있다.

### 5.5 진입점

```
uv run python scripts/rank_keywords.py 개발자            # 사람이 읽는 표
uv run python scripts/rank_keywords.py 개발자 --json     # 프로세스 경계용
```

파이썬에서는 `sns.research.rank_keywords(query, ...)` 하나면 된다. 토글 4종(소스별 ·
밴드 on/off와 경계값 · 교차검증 하한 · 제외 키워드)이 전부 인자로 열려 있다.
