# 06. 미디어 렌더 (이미지 · 영상 · TTS)

> 상위: [PLAN.md](../PLAN.md) · 관련: [05-콘텐츠생성-품질게이트](05-콘텐츠생성-품질게이트.md)

## 1. 요구사항 (FR-M)

| ID | 요구사항 | 수용기준 |
|---|---|---|
| FR-M1 | 이미지 카드 = Pillow 결정론 렌더(`media_spec`→PNG) | 같은 spec→같은 checksum |
| FR-M2 | **영상 = 템플릿 코드 합성**: 자막+슬라이드+TTS 합성. 생성형 비디오 모델 미사용 | 같은 spec→같은(또는 안정적) 산출, 릴스/쇼츠 규격(세로 9:16, 길이 제한) 충족 |
| FR-M3 | 렌더 산출은 `media_asset`(kind·storage_url·checksum) 저장, 호스팅은 추상화 seam | 저장소 벤더 교체 1지점 |

## 2. 렌더러 결정 자료 [v2 — Phase 0 품질 스파이크에서 확정]

| | ffmpeg + ASS 자막 | Remotion |
|---|---|---|
| 단어별 하이라이트 자막(요즘 쇼츠 표준) | 카라오케 태그로 가능하나 바운스·박스 스타일 한계 | 공식 captions 패키지로 기성품 수준 |
| 렌더 속도(60초 영상) | 수십 초 | 수 분 |
| 디자인 반복 | 렌더해봐야 보임 | 브라우저 실시간 프리뷰 |
| 라이선스 | 무료 | 무료(3인 이하 팀·상업 허용 명시) |
| 스택 | CLI — Python 코어와 자연 결합 | Node — 렌더는 별도 프로세스라 공존 가능 |

- **moviepy는 후보 제외 권장** — 렌더 속도·자막 표현력 열위(2026-08 조사).
- Phase 0 스파이크에서 양쪽 샘플 각 1건 제작 → 팀 판정으로 확정.

## 3. TTS 결정 자료 [v2]

- **권장: Google Cloud TTS Chirp 3 HD** — 한국어 무료 최상급, **월 100만 자 무료**(일 4건 ≈ 한도의 6%), 상업 이용 명시 허용, SSML `<mark>`로 **단어별 타임스탬프**(자막 싱크 필수 입력)를 합성과 동시에 획득.
- **edge-tts 메인 금지** — CI(데이터센터 IP)에서 403 차단 반복 + 약관 그레이존. 로컬 폴백만.
- 백업: Kokoro-82M(Apache 2.0, CPU 구동) — 완전 오프라인 필요 시.

## 4. 품질 수치 가이드 [v2 — 딥리서치 근거]

- **안전영역**: 텍스트·핵심 요소는 **중앙 900×1400 박스** 안(릴스 상단 210/하단 310/우측 84px, 쇼츠 상단 120/하단 300/우측 96px가 UI에 가림). 한 벌 렌더로 릴스·쇼츠 겸용. 렌더 후 코드 가드 검증(FR-A2).
- **시각 페이싱**: 2~4초마다 화면 변화(씬 전환·줌·요소 등장) — faceless 영상에서 얼굴을 대체하는 리듬.
- **BGM**: 플랫폼 중립 무료 음원(Pixabay Music 등)으로 통일. YouTube Audio Library는 유튜브 밖(인스타) 사용이 트랙별로 애매해 크로스포스팅에선 배제.
- **자체 그래픽**: 코드 화면·직접 그린 도표를 매 영상에 포함 — 콘텐츠 정책 안전(NFR-11, [12](12-비기능-테스트.md))의 요건이자 개발 니치의 차별점.
