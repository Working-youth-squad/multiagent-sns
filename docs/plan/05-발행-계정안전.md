# 05. 발행·계정 안전

> 담당 역할: **역할 A (파이프라인·인프라)** · 관련 요구사항: 2, 7, 10, 11 · 상위 문서: [기획서 총괄](../기획서.md)
> 이식 기반: feedr-clone `publish-runner`(발행 큐 처리) + `providers/`(어댑터 패턴)

## 1. Provider 어댑터 (요구사항 2 — 차후 SNS 확장 대응)

feedr-clone의 `Provider` 인터페이스 계승: `authUrl / exchangeCode / refresh / publish / fetchChannelStats / fetchPostInsights`.
**새 SNS 추가 = 파일 1개 작성 + registry 등록**으로 끝나는 구조.

- `youtube.ts`: 이식 (Google OAuth2 refresh token, resumable upload) — 거의 무수정
- `instagram.ts`: **신규** (§2)

## 2. Instagram provider (신규 개발)

feedr-clone `threads.ts`(같은 Meta 계열 — 장기토큰 교환·2단계 발행 패턴 동일)를 본떠 작성.

- **사전 요건**: IG 프로페셔널 계정 + 연결된 Facebook 페이지, Meta 앱 권한 `instagram_content_publish`·`instagram_basic`·`instagram_manage_insights`·`pages_show_list`
- **발행 (2단계, 멱등 필수)**:
  1. 컨테이너 생성 — `POST /{ig-user-id}/media` · 피드 이미지: `image_url` / 릴스: `media_type=REELS, video_url, share_to_feed=true` (미디어는 스토리지의 공개/서명 URL)
  2. 상태 폴링 — `GET /{container-id}?fields=status_code` → `FINISHED` 대기 (영상은 수십 초)
  3. 게시 — `POST /{ig-user-id}/media_publish?creation_id={container-id}`
  - 컨테이너 ID를 `publish_attempts.container_id`에 저장 → 크래시 후 재시작 시 **컨테이너 재사용**(이중 발행 방지)
- **인사이트**: `GET /{media-id}/insights?metric=views,reach,likes,comments,saved,shares` / `GET /{ig-user-id}/insights?metric=follower_count,reach&period=day`
- **한도**: 발행 API 24시간당 25건(계정당) — 일 1건 운영이라 여유, 코드 상수로 상한 강제

## 3. 발행 러너 (publish-runner.yml — 15분마다, `concurrency`로 단일 실행)

feedr-clone 파이프라인 계승:

```
1 멈춘 작업 복구 (10분 이상 publishing 상태 → 재큐)
2 발행 시각 도래 항목 클레임 (Postgres: SKIP LOCKED / 타 DB: 직렬 실행이라 불필요)
3 토큰 만료 5분 전이면 자동 refresh → 재암호화 저장
4 provider.publish() 호출
5 결과 처리:
   성공         → published + external_id 기록 + Discord 성공 알림
   스팸 차단     → 서킷브레이커: 재시도 없이 실패 + 해당 채널 오토파일럿 자동 OFF + 경보
   인증 만료     → 채널 expired 전환 + 재연동 알림 (재시도 안 함)
   쿼터 초과     → 다음 창까지 대기 + 알림
   일시 오류     → 지수 백오프 2^n분, 최대 3회
```

## 4. 스팸·계정 안전 (요구사항 10)

- **공식 API만 사용** — 비공식 클라이언트·스크래핑 발행 금지 (계정 정지 1순위 원인 차단)
- **빈도 상한**: 계정당 일 1건 (`DAILY_PUBLISH_LIMIT=1` 코드 상수). IG 25건/24h·YouTube 쿼터(업로드 ≈1,600units, 일 10,000)의 극히 일부만 사용
- **워밍업**: 계정 개설 직후 1주는 격일 1건 + 프로필 완성(사진·소개·링크)을 사람이 직접. 개설 즉시 API 발행은 스팸 신호
- **발행 시각 지터**: 슬롯 시각 ±0~10분 랜덤 (기계적 정시 발행 패턴 회피)
- **서킷브레이커**: Meta "API access blocked" 감지 시 즉시 해당 채널만 중지 — 다른 채널 영향 없음
- **콘텐츠 측 방어**: [04-영상제작](04-영상제작.md) §5 (독창성 구조·템플릿 다양화)

## 5. Discord 알림 (요구사항 11)

- **발신 지점**: ① publish-runner 성공/실패 처리부 ② agent-cycle·analytics-sync 최상위 catch
- **구현**: Discord 웹훅 URL(secret)로 `POST { embeds: [...] }` — `notify.ts` 함수 하나(~30줄)
- **알림 내용**:
  - 발행 성공: 계정·플랫폼·글 제목·링크
  - 발행 실패: **오류 분류**(`auth`/`quota`/`spam_block`/`transient`/`render`) + 원문 에러 + **LLM 원인 분석 1줄** (Gemini에 에러 컨텍스트 → "원인과 조치를 한 문장으로", LLM 실패 시 분류명만이라도 발송)
  - 토큰 만료 임박, 서킷브레이커 발동
- 모든 알림은 `notifications` 테이블에도 적재 → [07-웹화면](07-웹화면.md) 알림 로그와 이중화
